## 0. 총평

기능 축은 계약대로 서 있다 — 매트릭스의 개인>팀 대체, executive 전권, 단가 4중 잠금, 규칙 부재 = 현행 허용,

- **`screenRuleOf`의 catch가 완전 무음** — 영구 fail-open을 관측할 방법이 없다(같은 상황에서 핸들러는 `console.error`를 남긴다 — 비대칭). `server/index.cjs:379`
- **w4b 0.5단 매처가 넓다** — `/CHECK|constraint/i`라 UNIQUE·NOT NULL 위반도 "단가 CHECK 거부"로 초록. `e2e-w4b.mjs:54`
- **w4b 6단 "'E2E' 잔재 0"은 사실상 공허** — 코드가 아니라 복사본 스냅샷 상태를 보며, 2개 컬럼만 검사한다(inspector·lot·calendar 등 미검사). 회귀 통과 건수로 계상하기엔 부적절. `e2e-w4b.mjs:148`
- **w4c 쓰기 0 검산이 호출 채널의 1/4만 덮는다**(3표만 확인, equipment·mold·item·spec·calendar·app_config 미검산). `e2e-w4c-desktop.mjs:86`
- **세션 유휴가 "HTTP 활동" 기준** — 전광판 폴링 탭을 열어두면 세션이 영구 연장된다. `auth.cjs:66-77`

## 4. 슬러지

- **S-1 (즉시 처분 권고)**: `m1-desktop-check.mjs`(105줄)와 `m1-attach-check.mjs`(89줄)가 **85% 복붙 쌍둥이**이고,
  **같은 파일명으로 증거 스크린샷을 쓴다** — 배치C 문서가 M-1 통과 증거로 인용한 `captures/M1_desktop_reject_260813.png`를
  desktop-check 한 번 실행으로 덮어쓴다. 게다가 desktop-check는 라이브 앱을 **스스로 spawn** 해 "앱 실행은 사람 손" 규약과 충돌.
- **S-2**: `check`/`login`/`api`/쿠키 파싱이 **하네스 19개에 복제**되고 시그니처가 두 갈래로 갈렸다(`api(ch,body)` 13개 vs `api(cookie,ch,body)` 2개).
  → `scripts/lib/e2e.mjs` 공용화 시 **C-2·M-13·M-17이 한 번에 닫힌다**(슬러지 정리가 아니라 사고 방지의 구조적 해법).
- **S-3**: KST 날짜식 `Date.now() + 9*3600e3`가 **5벌 복제** — `src/shared/date-kst.ts` 주석이 "3중 복제를 공용 승격했다(8/11 슬러지 지적)"고 적어둔 그 패턴이 scripts/에서 재발.
- **S-4**: `e2e-pc1.mjs:74`는 반대로 **UTC** `new Date().toISOString()` — KST 00~09시 실행 시 전날(7/30 날짜 사고 패턴).
- **S-5**: `SAVE_DIALOG_CHANNELS`의 죽은 키 3개(`fmea:export`·`report:export`·`sqReport:export` — 마지막은 저장소 어디에도 없는 채널). M-1의 오타 출처.
- **S-6**: `permStore.canRead()` 호출처 0건(죽은 API) · `e2e-pc1.mjs:129` `void prod2` · `m1-attach-check.mjs:49` 불필요한 도메인 활성화.
