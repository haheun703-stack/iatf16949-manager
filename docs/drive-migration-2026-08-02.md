# 드라이브 이사 — 작업 정본을 D(내장)에서 E(USB 외장)로 (2026-08-02)

> 결과: 프로젝트 폴더 403GB가 외장으로 이사. D 여유 79.8GB → 506.9GB.
> **작업·커밋 정본 = `E:\00. 클로드 봇 프로그램 모음_260801\IATF16949,SQ 자동작성 봇\`**
> D의 프로젝트 폴더는 **전량 삭제**했다(대조 후).

이 문서를 저장소에 남기는 이유: 이사 기록이 메모리(이 PC 안)와 프로젝트 루트 대장(외장 안)에만
있으면 **USB가 죽을 때 같이 죽는다.** 아래 절차는 재현 가능해야 한다.

## 1. 드라이브 문자가 바뀌었다 — G가 아니라 E다

이사 계획서(프로젝트 루트 `28_이사준비_경로대장_260802.md`)는 외장을 `G:` 로 적었다.
실행 시점에 **`E:` 로 잡혔고, `G:` 는 구글드라이브 가상 마운트**가 가져갔다.

```
E:  SAMSUNG   3,726GB   Samsung Y3 (USB)   ← 외장. 작업 정본
D:  새 볼륨     585.9GB   NVMe 2번 파티션      ← 비움. 여유 506.9GB
C:            366GB     시스템             ← 라이브 DB. 이사와 무관
```

⚠️ **USB 드라이브 문자는 고정이 아니다.** 경로를 쓰기 전에 반드시 실체를 확인한다.

```powershell
Get-Disk | Where-Object BusType -eq 'USB'
Get-Volume | Where-Object FileSystemLabel -eq 'SAMSUNG'
```

## 2. ⚠️ 260자 함정 — 이번 이사의 진짜 위험

**탐색기 복사가 417개 파일을 오류 한 줄 없이 건너뛰었다.**

원인은 목적지 경로 접두사가 더 길다는 것뿐이다.

```
D:\IATF16949,SQ 자동작성 봇\                              22자
E:\00. 클로드 봇 프로그램 모음_260801\IATF16949,SQ 자동작성 봇\   48자   (+26자)
```

D에서 251자였던 파일이 E에서 277자가 되어 윈도우 `MAX_PATH`(260)를 넘는다.
`LongPathsEnabled=1` 이 켜져 있어도 **탐색기 복사 엔진은 조용히 실패한다.**

| 폴더 | 누락 | robocopy 복구 후 |
|---|---|---|
| `TPC AM사업부 품질폴더` | 381건 | 0 |
| `1-1 MES 작성자료` | 16건 | 0 |
| `IATF,SQ 각 팀별 구분 모음_260701` | 20건 | 0 |
| **합계** | **417건** | **0 · 실패 0** |

빠진 것이 하필 **심사 자료**였다 — `B-2100 시정조치 규정` 양식 20종(시정·예방조치 요구서,
4M변경 관리대장, 고객불량 유효성 점검 관리대장, 유효성 점검 체크시트),
`25467-82600` ISIR 도면·기술사양변경서.

### 규칙

- **복사는 `robocopy /E`** — 롱패스를 내부적으로 처리한다. 탐색기 드래그 금지.
- **삭제도 롱패스가 문제** — `Remove-Item` 은 260자 초과에서 잔재를 남긴다.

  ```powershell
  [System.IO.Directory]::Delete('\\?\' + $path, $true)
  ```

  읽기전용 속성이 걸린 폴더는 삭제가 중간에 멎는다. 먼저 속성을 내린다.

  ```powershell
  foreach ($f in [IO.Directory]::EnumerateFiles($lp,'*','AllDirectories')) {
    [IO.File]::SetAttributes($f, [IO.FileAttributes]::Normal)
  }
  ```

- **대조는 파일 수 + 총 바이트를 둘 다** 본다. 바이트만 보면 작은 파일 누락을 놓친다.
  이번에 1-1 MES 작성자료는 **바이트가 소수점 둘째 자리까지 같은데 16건이 비어 있었다.**

## 3. DB 경로 재적재 — 정확히 7건

라이브 DB(`%APPDATA%\iatf16949-manager\iatf16949.db`)는 C에 있고 이사와 무관하다.
그러나 **그 안에 파일시스템 경로가 7건 박혀 있다.** 폴더를 옮기면 전부 죽는다.

| 위치 | 건수 | 적재한 곳 |
|---|---|---|
| `company_profile.value` (mastersDir) | 1 | 설정 |
| `isir_packages.source_path` | 5 | 마이그 **0041**(1) · **0075**(4) |
| `app_config.value` (mes drop_dir) | 1 | 마이그 **0073** |

### ⚠️ 마이그 0041은 최초 조사에서 놓쳤다

`0041_isir_28237_2maa1.sql:7` 이 소문자 `d:\` 로 시작한다. 대문자로만 검색해서 빠졌다.
**경로 검색은 반드시 대소문자 무시로 한다.**

```powershell
# 이렇게 찾는다
rg -i '[dD]:[\\/]{1,2}IATF16949' resources/migrations
```

### 재적재 절차 (문자가 또 바뀌면 그대로 다시 돌린다)

전 테이블·전 컬럼을 `LIKE '%IATF16949,SQ 자동작성 봇%'` 로 훑어 **접두사만** 바꾼다.
반드시 ①예행 → ②대상 실재 확인 → ③적용 순서로 한다.

```js
const OLD = 'D:\\IATF16949,SQ 자동작성 봇';
const NEW = 'E:\\00. 클로드 봇 프로그램 모음_260801\\IATF16949,SQ 자동작성 봇';
// 대소문자 무시로 접두사 일치 확인 (0041 이 소문자 d:\ 다)
const i = String(v).toLowerCase().indexOf(OLD.toLowerCase());
if (i !== 0) continue;                 // 접두사가 아니면 건너뛴다
const next = NEW + String(v).slice(OLD.length);
if (!fs.existsSync(next)) continue;    // 대상이 실재할 때만 쓴다
```

⚠️ `better-sqlite3` 는 Electron ABI 로 빌드돼 있어 시스템 node 로는 못 연다.

```powershell
$env:ELECTRON_RUN_AS_NODE='1'
& .\node_modules\electron\dist\electron.exe script.js
```

### 이 작업은 마이그가 아니다

경로는 **설치 환경마다 다른 값**이다. 마이그로 만들면 TPC의 `E:\` 가 모든 설치본에 박힌다.
`fill_item_names.py`(7bc56d5) 와 같은 판단 — 저장소 밖 환경 값은 스크립트로 다룬다.

## 4. 클로드 코드 기억은 폴더 경로로 묶인다

`~\.claude\projects\<키>\` 에 메모리와 대화 이력이 있고, **키는 작업 폴더 경로에서 만들어진다.**
규칙 = **영숫자가 아닌 문자 1개당 `-` 1개**(한글 1음절도 `-` 1개).

```
d:\IATF16949,SQ 자동작성 봇                              →  d--IATF16949-SQ-------
E:\00. 클로드 봇 …_260801\IATF16949,SQ 자동작성 봇        →  e--00----------------260801-IATF16949-SQ-------
```

**폴더를 옮기고 그냥 열면 다른 프로젝트로 잡혀 기억이 백지가 된다.**
이사할 때 구 키 → 신 키로 폴더째 복사한다(NTFS는 대소문자를 구분하지 않으니 한 벌이면 된다).

## 6. 추기 (2026-08-04) — 문자가 정말 또 바뀌었다: E → H
