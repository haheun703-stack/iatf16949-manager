## 1. 🔴 Critical (8건) — 즉시/오픈 전 필수

### C-1. 무인증 계정 점유 — NULL 해시 = 아무 비번 설정 `server/auth.cjs:40-45`
`password_hash`가 NULL인 계정에 로그인하면 **요청자가 보낸 비번을 그대로 설정**한다. 로그인은
인증 미들웨어 앞이고 ID가 실명이라, HOST 개방 시 사내망 누구든 아직 로그인 안 한 계정(대장 미결
3건 + 일괄발급 전 전원)의 이름만 알면 executive 계정을 점유한다. **→ W4 전 필수.**

### C-2. 143/147 채널 권한 무가드 `server/index.cjs:195-200`
`PROTECTED`가 4채널만 덮는다. `form:submissionDelete`·`obligation:delete`·`schedule:delete`·
`company:profileSave` 등 나머지가 role `member`도 무제한 호출 가능 → 신입 한 명이 타 팀
작성기록(=심사 증거) 전량 삭제 가능. index.cjs:326의 바인딩 가드레일 조건("권한 가드 후")이
4/147만 충족. **→ W4 전 필수.**

### C-3. 무제한 4자리 숫자 비번 `server/index.cjs`(정책)
비번=4자리 숫자 고정 + 시도 제한·잠금·지연 전무. 키공간 1만 + 무제한 시도 → 스크립트 하나로
임의 계정(경영진 포함) 탈취. 대장이 "조직도 순서 연속숫자"라 실효 공간은 더 작다. **→ W4 전 필수.**

### C-4. 실비번 git 커밋 — 고정 3건 `scripts/setup-passwords.cjs:37-39`
`['서상규','0000'],['하헌','1111'],['서규하','2222']`가 소스에 평문. `must_change_pw=0`이라
계속 유효. 리포 접근자 누구나 로그인 가능 + 히스토리 잔존(파일 수정으로 제거 불가). **→ 비번
재발급 + 코드에서 제거(대장은 리포 밖 원칙 위반).**

### C-5. 실비번·인사 일지 git 커밋 `TODO_사무실에서_이어서.md`
운영 일지(158KB)가 git 추적 중이며 본문에 "하헌 비번 1111"(87·97행)·"이정훈 …0123·
executive"(277행) 등 실계정 비번 기재. "대장은 repo 커밋 절대 금지" 원칙이 이 파일로 우회 유출.
**→ 파일을 gitignore + 비번 제거판으로 교체(과거 커밋은 재발급으로 무력화).**

### C-6. 신규(미시드) DB 기동 불가 — 0046 FK 실패 `resources/migrations/0046_ppap.sql:49-72`
데모 시드가 `clause_id`·`team_id` FK를 참조하는데 `clauses`/`teams`는 `seedDatabase()`가
`runMigrations()` **이후** 채운다. FK ON 드라이런에서 0046·0048·0055 실패 실측 → 빈 userData
첫 기동 시 `runMigrations()` throw → **무증상 사망**. **W4 새 서버PC·설치판 클린 설치 직격.**

### C-7. 엔진: 수식 셀 파괴를 verify가 통과 `src/main/docgen/form-export-engine.ts:165-189, 407`
수식 셀에 문자열 대입 시 수식이 소리 없이 교체되고, 재검증은 `got === r.value`라 파괴를 성공
판정. **오늘 스캔 40건이 그대로 깨진 채 all-green 출하 가능.** 방어 지점 = `injectCell` 진입부
수식 검사 + skip 리포트(`markOptionCells`·fmea `put`도 별도 적용).

### C-8. 엔진: 병합 비앵커 쓰기 파괴를 verify가 은폐 `form-export-engine.ts:165, 307`
병합 슬레이브에 쓰면 앵커(양식 라벨)가 파괴되는데, 재검증이 슬레이브를 읽으면 앵커값(=주입값)이
돌아와 통과 + 병합 개수 불변이라 `mergesOk`도 통과. **라벨 지워진 파일이 3중 verify 전부 초록으로
출하.** (메모리의 "신규 매핑 시 E2E 필수" 원인이 이 검증 사각.) 방어 = render-model.ts:121-131
슬레이브 판정 재사용해 앵커 리다이렉트.

### 렌더러 C(1건). 초안 열기 경합 파괴 `FormListPanel.tsx:37-44`
`useEffect` deps에 `pendingSubmissionId` 포함 + 내부에서 null 세팅 → 이펙트 2차 실행이
`loadFormDefinition`으로 진입해 방금 연 초안 값을 빈 양식으로 덮음 → 저장 시 **초안 수정이 아니라
중복 제출본 생성**. 수정 = 소비 로직을 이펙트 밖(핸들러)로 옮기거나 ref 가드.
