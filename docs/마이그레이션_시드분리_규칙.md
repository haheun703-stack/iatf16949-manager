# 마이그레이션 시드 분리 규칙 (0058부터 적용)

제품화 감사(2026-07-06, [[plan-productization]])의 "3층 팩 아키텍처" 준비 규칙.
목표: 나중에 코어(판매용)와 TPC팩(기밀·배포금지)을 **마이그레이션 파일 단위로** 골라낼 수 있게 한다.

## 규칙

1. **한 파일 = 한 종류.** 스키마(DDL)와 데이터(DML)를 한 마이그레이션에 섞지 않는다.
   - 스키마 전용: `CREATE/ALTER/DROP/INDEX` 만. 헤더에 `[스키마 전용 마이그레이션 — 데이터 없음]` 표기.
   - 데이터 전용: `INSERT/UPDATE/DELETE` 만. 헤더에 `[데이터 전용 마이그레이션 — 스키마 변경 없음]` 표기.
2. **TPC 전용 데이터에는 `[TPC팩 후보]` 를 추가 표기.** 기준: 회사 실명·실주소·임직원 이름,
   실거래 품번/고객사, TPC 정본에서 추출한 규정 본문·양식 시드 등 — 타사 배포판에 실려선 안 되는 것.
   업종중립 카탈로그(IATF 조항, AIAG 코어툴 구조, APQP 43산출물 등)는 해당 없음.
3. 파일명도 성격이 드러나게: 스키마는 `_schema`, 데이터는 내용 서술형(예: `0059_reg_doc_rows_and_team_fixes`).
4. 예외 없음. 스키마+초기데이터가 함께 필요하면 번호를 2개 쓴다(N=스키마, N+1=데이터).

## 왜

- 마이그 0001~0057 은 순수스키마 16 / 범용카탈로그 5 / 혼합 9 / TPC전용 26 으로 뒤섞여 있어
  팩 분리 시 파일 내부를 쪼개야 한다(감사 지적). 0058부터는 새 부채를 만들지 않는다.
- 분리돼 있으면 클린 배포 채널 구축이 "파일 선별 + content_packs 태깅"으로 끝난다.
