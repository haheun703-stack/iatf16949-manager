## 1. 처분 4건

| # | 결함 | 처분 |
|---|---|---|
| Minor 11 | bridge 공용 DB 연결에 `busy_timeout` 없음 → authDb(4000ms)와 잠금 경합 시 SQLITE_BUSY 즉사 | `connection.ts`에 `busy_timeout = 4000` 1줄(authDb 와 동일값 — 실측 확인) |
| Minor 10 | 다운로드 토큰 = Math.random + 소유 세션 미바인딩 → 로그인자 간 선취 가능(30분 창) | `crypto.randomBytes(16)` + 발급 세션(sid) 바인딩 — 타 세션 GET = **403**(fail-closed: sid 미기록 토큰도 403). 1회 소진(404) 회귀 유지 |
| Minor 3 | `window.prompt` Electron 미지원 → 데스크톱에서 비번 재설정 버튼 무반응 | `UserManageModal` 행 하단 **인라인 입력 패널**로 교체(웹·데스크톱 동일). 4자리 검증·M-10 통지 로직 종전 그대로 |
| M-6 | role 은 로그인 시점 스냅샷 → app_users 변경이 기존 세션에 반영될 길 없음(B′ N-7 남은 절반) | `auth.invalidateUserSessions(userId)` 신설 + 디스패처 배선: **upsert = role/active 실변경 시만**(이름·팀 무해 편집은 로그아웃 없음), **delete·resetPassword = 무조건**. 실패해도 응답은 정상 진행(try/catch) |

## 2. 실증 — `scripts/e2e-dgroup.mjs` 신설 (17건 · README-e2e §2 등재, 활성 9종 170건)

- 0단 이중 세션(같은 E2E봇·다른 sid — "로그인자 간" 등가 재현)
- 1단 Minor 10: 토큰 crypto 32hex · **타 세션 403** · 발급 세션 200(169,210B) · 재수령 404
- 2단 M-6 upsert: 무변경 재저장 → 세션 생존 / role 실변경 → **대상 세션 전량 401** / 원상 복귀
- 3단 M-6 resetPassword: '0000' 재설정 → 세션 401 → **원 해시 바이트 원복**(복사본 한정 RW 1회) → 재로그인 정상
- 종료: app_users 행수·E2E봇 role 원상 — 잔여물 0
- ⚠ 자기정정 1건: 첫 실행 15/17 — 하네스가 resetPassword 에 7자 비번을 보내 4자리 정책(관리팀 대장)에
  걸림. **결함이 아니라 하네스 오류** — 4자리+해시 원복 방식으로 정정 후 17/17.
