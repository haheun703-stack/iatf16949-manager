## §4 3차 신규 발견 (1·2차에 없던 것)

1. **REVISION 각인** — 검사기준 개정판(REVISION 일자)이 검사 실적 행에 그대로 찍힌다
   (품질검사내역_M XLS에 REVISION 컬럼 실증). "검사기준 최신판 사용 증거"가 자동 성립 —
   **IATF 심사 문법과 정확히 일치. 데일리Q 기록 5종에 revision 각인 채택 가치 높음.**
2. **초중종 3회 문법** — 자주검사는 초품/중품/종품 3레코드가 기본 단위. 생산실적 XLS에도
   초품/중품/종품 + 설비일상점검 컬럼 동봉 = 실적과 검사가 한 행에서 교차 검증됨.
3. **검사자+확인자 2단 서명** — 모든 검사·점검 기록에 확인자(승인) 열 존재. 데일리Q ✓와 동형.
4. **참조1~9 확장 슬롯 + 논리삭제**(사용유무 해제+제외코드보기) — 마스터 설계 관행.
5. **필수 = 컬럼명 앞 빨간 ＋** · 계산열 초록 · 탭 누적 MDI · 즐겨찾기(개인화).
6. **금형 수명 계약의 실물** — 마스터에 허용타발수(총누적/연마후)·등급별 기준, 실적은 일자별
   타발수→누적 가산(작업설비·실적번호와 연결). 26번 A4가 "계약에 없다"던 테이블의 원형이 여기 있다.
7. **KPI 13지표가 이미 정의돼 있음** — 영업 3(매출·매입+사급·부가율) / 재고 4 / 생산 3(UPH·가동률
   ·VPH) / **품질 3(고객불량건·공정불량율 PPM·CPU 원/EA)**. 26번 A5(KPI 수치 확정)는 신규 발명이
   아니라 **이 13개에 정렬**하는 문제.
8. **TV현황판 실물(그림65)** — 설비별 도넛 타일: 달성률% 중앙 + 지시/수집/생산/불량 4행 +
   품번·공정명 하단. 1차 노트의 "다크+도넛+신호등" 문법의 운영 실물.

## §5 XLS 9종 헤더 (기계 판독 성공 — 파서 설계 자료)

생산 5종: 지시대비실적(12열) · 생산실적상세현황(**40열** — 초중종·설비일상점검 포함) ·
일별_월별 생산현황(13열) · 주간생산계획(158열 — 일자 반복) · 계획대비실적(103열).
품질 4종: 수입검사내역조회(20열 — 검사결과·불량내역·검사자) · 품질검사내역_M ×3(20열 공통 —
LOTNO·초중종·REVISION·검사자/확인자/품질(합)).
⚠️미열람: 금형마스터등록·수주등록·매출관리·제품출고금액조회 4종(2선).

## §6 데일리Q 매핑 — 판단 재료 (확정은 29번 트랙)

| MES 모듈 | 데일리Q 처리 | 근거 |
| --- | --- | --- |
| 기준정보 | **채택(M0 확장)** — 품목·거래처·BOM·공정 기보유. 보강 후보 = 코드 2단(참조 슬롯)·논리삭제·역전개 조회 | §2 |
| 생산 | **핵심 채택** — 작업지시·실적(초중종 연동)·불량. 계획(주간 매트릭스)은 2단계 | 기록 5종 계약 |
| 품질 | **핵심 채택** — 자주/패트롤/수입 3검사 + SPEC/REVISION + 확인자 2단. X-bar R는 Cpk 스파이크 기존재 | §4-1·2·3 |
| 설비 | **채택** — 일상점검(점검자+확인자, NOMINAL±Tol 기준·리비전) | §3-9 |
| 금형 | **부분** — 타발수 계약은 이 실물 구조로 봉합 가능(26번 A4 재료). 착수는 별도 판단 | §4-6 |
| 자재 | **부분** — 입하/입고·재고현황(안전재고 신호등)은 가치. 발주·매입(돈)은 경계 밖 | 헌법 §1-1 |
| 영업 | **제외(돈)** — 단, 수주 **수량**은 작업지시의 원천이라 접점만 유지(단가·금액 무) | 헌법 §1-1 |
| 개발 | **제외(2선)** — 문서첨부형 3화면은 APQP 문서 링크 참고만 | — |
| 경영정보 | **부분** — KPI 13지표 정렬(A5 흡수). 금액 현황은 제외 | §4-7 |
| 관리자 | 기보유(app_users·권한) — **현장용 권한 분리(AUTHWORK·PGBN W) 관행 참고** | §2 |

**팀별 허브 시사점**: MES의 정보 구조 = "모듈(팀) → 메뉴 → 입력/조회"이며 입력 화면은 팀당
1~4개뿐이다(§3). 데일리Q "오늘 이 N개만" 원칙의 실증 — **팀원이 매일 여는 화면은 원래 적다.
302종이 아니라 §3의 10줄이 팀원의 하루다.**

> **채택 확정(8/4 오후, 코워크 검토 → 29번 §10 추기로 접수)**: ①이 매핑표가 PB·PC 화면 설계
> 준거로 명시됨 ②§3 트리는 SQ 미니멀 팩(29번 §5)과의 **교차 검증 기준**("매일 여는 화면 1~4개
> 안에서 SQ 역산 문서가 쌓이는가")으로 채택 ③§4-1 REVISION은 **기록 시점 스냅샷**(참조 금지)
> 조건부로 쓰기 채널 스키마에 반영 예약 — 상세는 29번 §10.
