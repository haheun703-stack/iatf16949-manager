# M1 선행분 견적서 — 입고·출하 사진함 (2026-07-28, 스트림 B · W4 무관 범위)

> 근거 = 15번 지시서 §0.5-2(원버튼 사진함, 현장 입력 0) + 코워크 설계 판정 3건(7/28) +
> **전표 실물 4장 실측**(`입고출하전표_샘플_260728/`). 촬영 화면 배포는 W4 후 유지(15번 §1-7 불변).
> **이 문서는 착수 전 견적 — 코워크 검수 + 사장님 재가(수집함 1개 태그안) 후 구현.**

## 0. 전표 4장 실측 판독 (설계 근거)

| 전표 | 공급자 | 방향 | 품목 | 서식 특성 |
| --- | --- | --- | --- | --- |
| 입고1 | 세일에스앤티 | →TPC 입고 | **5품목**(24451-07870 1,500 외) | 수기 거래명세표·QC 도장·인수자 서명 |
| 입고2 | SW테크 | →TPC 입고 | **2품목**(28236-2MAA0 3,000 · 25457-2MHE0 2,000) | 전산 명세표·인수자 빈칸 |
| 입고3 | 휴먼테크 | →TPC 입고 | **3품목**(45264-3D900-O2 8,000 · 28237-2MAA1-P1 5,000 · 28236-2MAA0-4 4,000) | 전산·QC 도장·비고 일자 |
| 출하1 | **TPC** | TPC→SW테크 출하 | 1품목(2MAA0 조인트 4,000ea) | 수기 공급자용·인수자 서명 |

실측이 강제하는 설계 4가지:

1. **사진 1장 : 수불 N행 (1:N).** 4장 중 3장이 다품목 — 전표 1장이 mat_receipt 여러 행을 낳는 게 기본형.
2. **업체LOT는 전표에 없다(4/4).** vendor_lot 는 공란 허용 + 포장 라벨 사진 추가 촬영으로 보완(태깅 때 별건 첨부).
   "전표에 없으면 비워 둔다"가 정직 — 억지 기입 금지.
3. **외주 왕복이 실재한다.** TPC→SW테크 2MAA0 조인트 4,000 출하 → SW테크→TPC 28236-2MAA0 3,000 입고
   (같은 날). 수집함을 방 2개로 나누면 이 계보가 끊긴다 — **방 1개 + 유형 태그** 판정의 실측 근거.
4. **단가·금액 열은 구조화 금지**(경계 "돈은 안 만진다") — 사진 원본이 증거, 구조화는
   품번·수량·거래처·일자·업체LOT 5개만.

## 1. ⓐ 스키마 — 신규 테이블 0, 컬럼 추가 2 (마이그 0103 후보)

0101 코어에 **이미 있는 것**(실측): `mat_receipt`(receipt_date·item_code·vendor_lot·internal_lot·
partner_code·qty·cert_no·note·created_by) · `raw_captures`(kind·content·attached_path·form_code·status·
created_by) · `partner` 139행(자재공급처 113·외주처 6·고객 20) · `lot_registry`.

| 항목 | 안 | 근거 |
| --- | --- | --- |
| 사진 수집함 | **`raw_captures` 재사용** — kind=`receipt_in`\|`receipt_out`, status=`미분류`→`태깅완료`, attached_path=사진 | 신규 테이블 0 — 15번 "사진 우선→AI 판독 승격 경로"용으로 설계된 자리 그대로. 자동 기록 3개(시각·세션 사용자·유형)와 정합 |
| 사진↔수불 연결 | `mat_receipt.capture_id` 컬럼 추가 | 1:N 실측(다품목 전표) — N행이 같은 capture_id 참조 |
| 입고 구분 | `mat_receipt.receipt_class`(`원자재`\|`외주재입고`) 추가 | partner.partner_type 으로 초안 유도(자재공급처→원자재·외주처→재입고), 태깅 때 확정 — 명시 컬럼이 정직 |
| 출하 착지 | **구조화 테이블 신설 안 함**(봇 권고) — receipt_out 사진+태그(거래처·품번·수량·일자)는 raw_captures.content(JSON)에, LOT 스토리 종점 표시는 계보 조회에서 사진 참조 | 15번 경계 "창고·로케이션·수불부 금지" — 출하 구조화 테이블은 수불부로 가는 문턱. 필요해지면 파일럿 실측 후 별도 검수 |

## 2. ⓑ 사무실 태깅 화면 (템플릿 C — 분류표 리듬 그대로)

- **좌(380px)**: 사진함 목록 — 탭 [입고 \| 출하 \| 미분류], 행 = 썸네일·촬영시각·촬영자·상태 배지.
  숫자 밴드(ListKit) = 미분류 n·오늘 입고 n·오늘 출하 n.
- **우**: 사진 뷰어(원본 확대) \| 태깅 폼 — 거래처(partner 검색, 유형 표시)·품번(item_master 검색)·수량·
  일자(전표 일자)·업체LOT(공란 허용)·입고 구분(원자재/외주재입고, partner_type 초안) + **[품목 행 추가]**
  (다품목 전표 1:N). 저장 = mat_receipt N행 생성 + raw_captures status=태깅완료. 태깅 전 사진 =
  '미분류 입고 증거'로 유효(15번 §0.5-2 그대로).
- 기록 주체 = 세션 강제(STAMP), 미선택 시 우측 = 요약 카드(미분류 건수·오래된 미분류 TOP — 규칙④).
- 신규 채널: 목록/태깅 저장 2~3개(기존 semimes-handlers 에 편승).

## 3. ⓒ 전표 유형 판별 규칙 (M4 AI 판독 대비 — 지금은 규약만 확정)

1. **1차(현장, M1)**: 촬영 버튼 2개 [입고 전표]/[출하 전표] — 유형은 사람이 버튼으로 지정(입력 아님, 버튼 선택).
2. **2차(태깅, 사무실)**: 태깅 화면에서 유형 정정 가능(버튼 오촬영 교정).
3. **3차(M4 AI 판독, 후일)**: **공급받는자 칸=티피씨 → 입고 / 공급자 칸=티피씨 → 출하.** 실측 4장 전부
   이 규칙으로 판별 가능(입고1·2·3 = "TPC 貴下/티피씨 귀하", 출하1 = 공급자 (주)티피씨 인감).
   보조 신호: 전표 색(공급자용=황색), QC 도장=입고 측 부호. 사업자번호 515-81-13874(티피씨)가 어느 칸에
   있는지가 결정 신호 — 상호 표기 흔들림(티피씨/TPC/㈜티피씨)에도 안정.

## 4. 의무 연계 (코워크 추가 연결점 — 별도 엔진 금지 확인)

`receipt_in` 태깅 완료(mat_receipt 생성) → 기존 M3 데이터 트리거 ⓐ 확장으로
**"수입검사 이력카드 당일 기입"(SQ 2_2) 데이터 할 일 발행** — obligation_triggers 에 정의 1행 추가
(중복 방지 키 = 트리거 유형+입고일 버킷). 신규 엔진 0, M3 lazy 평가에 편승. 소멸 = 당일 수입검사
기록(insp_record 또는 L2100-07 작성기록) 감지 시 해소 표시(✓는 사람 — M3 규칙 그대로).

## 6. 질의 (착수 전 확인 3건)

1. **수집함 1개+유형 태그안** — 사장님 재가 대기(코워크 상신분). 재가 시 §1~2 그대로 구현.
2. **출하 착지 최소안**(§1 — 구조화 테이블 신설 없이 사진+태그, 수불부 경계 준수) 동의 여부.
3. **raw_captures 재사용안**(신규 테이블 0) vs 전용 테이블 신설 — 봇 권고 = 재사용(15번 설계 취지 그대로),
   파일럿에서 한계 확인 시 분리.
