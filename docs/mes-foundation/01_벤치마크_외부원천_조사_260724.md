# MES 파운데이션 벤치마크 — 외부 원천 검증 조사 (2026-07-24)

> 목적: 신기능 발굴이 아니라 **이미 세운 설계 가설 2개의 검증**.
>
> - **가설 ⓐ**: 중소기업 MES의 최소 공통분모 = 마스터 5종(공정/품목/BOM/라우팅/거래처) + 기록 3종(생산실적·검사스펙·검사기록) + LOT 라벨/추적. 이것으로 충분한가?
> - **가설 ⓑ**: "수집된 데이터를 개인/팀 할 일(TODO)로 자동 변환·배정"하는 기능은 기존 MES 제품에 없다. 차별점인가?
>
> 조사 원천은 지시된 3개 범위(수준확인제 기초/중간1, 국내 SME 상용 MES 2~3종, ISA-95/MESA-11 경계사전)로 한정. 조사일 2026-07-24, WebSearch/WebFetch 실측 기반. 확인 못 한 항목은 "확인 불가"로 표기.

## 1. 스마트공장 수준확인제도 — 기초/중간1 요구 항목

### 1-1. 제도 개요

- 운영: 중소벤처기업부(총괄) → 스마트제조혁신추진단(전담) → 확인기관(에스비씨인증원 등)이 진단·수준 측정. 자력으로 스마트공장을 구축한 중소·중견기업 대상, 확인 비용 전액 지원(기업당 최대 100만 원), 신청은 스마트공장사업관리시스템(www.smart-factory.kr).
  - 출처: [한국경영혁신중소기업협회 수준확인 제도 안내](https://www.kosre.or.kr/site/html/smart/factory.htm), [에스비씨인증원](https://www.sbcr.or.kr/site/html/smart/factory.htm), [2024년 수준확인 사업 공고(기업마당)](https://www.bizinfo.go.kr/web/lay1/bbs/S1T122C128/AS/74/view.do?pblancId=PBLN_000000000094473)

### 1-2. 수준 판정 기준 (KSMS 평가체계)

**평가 구성: 4개 영역, 10개 범주, 44개 항목, 1,000점 만점** (출처: [kosre.or.kr 수준확인 제도](https://www.kosre.or.kr/site/html/smart/factory.htm))

| 평가 영역 | 배점 | 내용 |
|---|---|---|
| 추진전략 | 160점 | 리더십·전략(100) + 프로세스 성숙(60) |
| 프로세스 | 420점 | 제품개발, 생산계획, **공정관리, 품질관리, 설비관리, 물류관리** |
| 정보시스템·자동화 | 400점 | 정보시스템(220) + 설비자동화(180) |
| 성과 | 120점 | 생산성·품질·원가·납기·안전·환경 |

**등급 판정(점수 구간)**:

| 등급 | 특성 | 점수 |
|---|---|---|
| Level 0 | 미인식·ICT 미적용 | ~550 |
| **Level 1 (기초)** | 식별 & 점검(Identified & Checked) — 부분 표준화, **실적정보 관리** | 551~650 |
| **Level 2 (중간1)** | 측정 & 확인(Measured & Monitored) — **생산정보 실시간 모니터링** | 651~750 |
| Level 3 (중간2) | 분석 & 제어 — 수집 정보를 분석해 설비 제어 | 751~850 |
| Level 4~5 (고도) | 최적화·자율 운영 | 851~ |

→ **Level 3 이상(중간2·고도)은 설비 자동제어 영역이므로 본 조사 범위에서 제외** (지시서 기준과 일치).

### 1-3. 수준별 정의 표 (추진단/보급사업 공통 정의)

출처: [세종테크노파크 스마트공장의 개념](https://sjtp.or.kr/bbs/center/center.php?bo_content=center02) (부산스마트제조혁신센터·울산TP 등 전국 TP 공통 게시 표)

|---|---|---|---|
| **기초** | 실적집계 자동화 | 공정물류 관리(POP) | 관리 기능 중심, 기능 개별 운용 |
| **중간1** | 설비데이터 자동집계 | 실시간 의사결정 | 기능 간 통합 |

| 고도 | IoT/IoS 기반 CPS화 | 비즈니스 CPS 네트워크 협업 | IoT/IoS화 |

**기초 수준의 핵심 기능(같은 출처)**: 생산 데이터 자동 집계, **자재 이력 추적(lot-tracking)**, **작업지시 시스템**. 기초 단계라도 "실시간 만들어지는 제품을 바로 집계해 관리, 자재 이력관리(lot-tracking)까지 가능"([뉴스핌 2020-11-11 기사](https://www.newspim.com/news/view/20201111001206)).

**중간1 수준의 핵심 기능**: 설비에서 자동 수집된 정보 기반의 **실시간 모니터링 및 품질분석**. 2025년 실무 안내로는 "설비·센서가 PLC를 통해 실시간 정보시스템(ERP·MES)에 연결, 실시간 모니터링·데이터 저장"([Polaris3D, 2025 수준확인 신청 정리](https://polaris3d.com/blog/trends/smartfactory-series-2/)).

### 1-4. 우리 설계와의 대응 (요약)

| 수준확인 요구 | 대응되는 우리 요소 |
|---|---|
| 기초: 실적집계 자동화 | 기록① 생산실적 |
| 기초: lot-tracking | LOT 라벨/추적 |
| 기초: **작업지시 시스템** | **가설 ⓐ 목록에 없음** → §4에서 판정 |
| 기초: 공정물류(자재 흐름) 관리 | **가설 ⓐ 목록에 없음(재고/수불)** → §4에서 판정 |
| 중간1: 품질분석(검사데이터 기반) | 기록② 검사스펙 + 기록③ 검사기록 |
| 중간1: 설비데이터 자동집계 | 스캔(Scan-to-Trace)·수기입력 혼합으로 부분 대응 — 설비 직결(PLC)은 범위 밖 |

## 3. ISA-95 / MESA-11 — 용어·경계 사전 (기능 카탈로그 아님)

### 3-1. ISA-95 레벨 (수직 계층 사전)

출처: [Tulip — MES, ISA-95, MESA-11 표준 비교](https://tulip.co/blog/mes-isa-95-mes-11-cmes-namur/), [SAP — What is MES](https://www.sap.com/korea/products/scm/digital-manufacturing/what-is-mes.html)

| 레벨 | 정의(1줄) |
|---|---|
| Level 4 | 경영·업무 계획(ERP) — 주/월 단위 |
| **Level 3** | **제조운영관리(MOM/MES) — 일/교대/시간 단위** |
| Level 2 | 감시·제어(SCADA/HMI/PLC) — 초 단위 |
| Level 1 | 센싱·조작(센서/액추에이터) |
| Level 0 | 물리적 생산 공정 |

### 3-2. MESA-11 기능 분류 (1997, 11개 — 각 1줄)

출처: [Symestic — The 11 Core MES Functions (MESA 11)](https://www.symestic.com/en-us/what-is/mesa-11)

| # | 분류명 | 1줄 정의 |
|---|---|---|
| 1 | Operations/Detailed Scheduling(세부 일정계획) | 설비·순서 기반 상세 생산 스케줄링 |
| 2 | Resource Allocation & Status(자원 할당·상태) | 설비·자재·인력 자원의 상태 추적과 할당 |
| 3 | Dispatching Production Units(생산단위 디스패칭) | 작업(오더)을 현장 단위로 내려보내고 흐름 조정 |
| 4 | Document Control(문서 통제) | 작업표준·도면·지시서 등 현장 문서 배포·개정 관리 |
| 5 | Data Collection/Acquisition(데이터 수집) | 공정·실적 데이터의 수동/자동 수집 |
| 6 | Labor Management(노무 관리) | 작업자 자격·투입·실적 관리 |
| 7 | Quality Management(품질 관리) | 측정치 분석·부적합 식별·시정 지원 |
| 8 | Process Management(공정 관리) | 공정 이상 감지·교정(설비 제어 연계) |
| 9 | Maintenance Management(보전 관리) | 설비·금형 점검/보전 계획과 이력 |
| 10 | Product Tracking & Genealogy(제품 추적·계보) | LOT/시리얼 단위 이력·역추적 |
| 11 | Performance Analysis(성과 분석) | 실적 vs 목표·과거 비교(OEE 등) |

### 3-3. 우리 범위(품질·사람 할 일)의 경계 대조

**해당하는 분류** — 우리 마스터5+기록3+LOT은 MESA-11 중:

- #5 Data Collection(기록 3종 = 수기+스캔 수집), #7 Quality Management(검사스펙·검사기록·SPC/CPK), #10 Product Tracking & Genealogy(LOT 라벨/추적), #4 Document Control(규정·양식 정본 관리 = 우리 앱의 본령), #11 Performance Analysis(부분 — KPI·계획대비실적), #6 Labor Management(부분 — "사람 업무 이행" 기록은 이 분류의 인접 확장).

**명시적으로 안 하는 분류** — #1 세부 스케줄링, #2 자원 할당, #3 디스패칭(설비 단위 작업 분배), #8 공정 관리(실시간 공정 제어), #9 보전 관리(예지보전 수준; 점검 '의무 기록'은 우리 방식으로 커버).

**ISA-95 축**: 우리는 Level 3의 품질·추적 슬라이스 + Level 4 인접(사람 업무·QMS 증거)을 다루고, **Level 0~2(센서·PLC·자동제어)는 명시적 제외** — 수준확인제 중간2 이상 제외와 정확히 같은 선.

**핵심 경계 발견**: "데이터→사람 할 일 변환"은 MESA-11의 11개 분류 **어디에도 독립 분류로 존재하지 않는다**. 가장 가까운 #3 Dispatching은 '생산 오더의 설비/라인 분배'이지 '개인/팀 업무 배정·완료 추적'이 아니다. 즉 표준 기능 모델 차원에서도 공백 지대다.

## 4. 가설 ⓐ 판정 — 마스터5 + 기록3 + LOT으로 충분한가?

**판정: 뼈대는 유효하나 "충분"은 아님. 시장 최소 공통분모에서 3개 요소가 빠져 있음(보완 필요), 2개는 선택.**

근거: §1 수준확인 기초 요건 + §2 상용 3종 교집합. 아래 표는 "조사한 3개 제품 모두에 존재 + 수준확인 기초/중간1 요구"에 해당하는데 가설 ⓐ 목록에 없는 것.

| 빠진 요소 | 증거 | 판정 |
|---|---|---|
| **① 작업지시(지시→실적 연결)** | 이카운트 '작업지시서', JNKC '작업지시', SystemEver '작업지시' — 3/3 존재. 수준확인 기초의 핵심 기능에 "작업지시 시스템" 명시(§1-3) | **필수 보완**. 생산실적은 시장 표준에서 항상 '지시 대비 실적'으로 존재. 지시 없는 실적은 계획대비실적·진척 현황이 성립 안 됨 |
| **② 자재 입출고/재고(수불)** | 이카운트 '수불관리', JNKC '자재관리'(입고/출고/창고별재고), SystemEver 재고·MRP — 3/3. 수준확인 기초 "공정물류 관리(POP)" | **필수 보완**. LOT 역추적(어느 자재 LOT이 어느 제품 LOT에 들어갔나)은 자재 입고·투입 기록 없이는 반쪽. 단, SME 최소형은 '자재 입고+투입' 2기록이면 되고 창고·수불부 전체는 불요 |
| **③ 불량 유형(마스터) + 불량실적(기록)** | 이카운트 '불량관리', JNKC 기준정보 '불량유형'+생산 '불량실적'+POP '불량등록' — 별도 축으로 존재 | **필수 보완(소형)**. 검사기록(합/부)과 별개로 '공정 중 발생 불량 수량·유형' 기록이 시장 표준. 우리 검사기록 스키마에 불량유형 코드+수량 필드를 넣으면 흡수 가능 |
| ④ 출하/납품 기록(+출하검사) | JNKC 제품관리(라벨발행·출고), 품질 '출하검사'; 이카운트는 영업모듈 소관 | 선택. 자동차부품 SQ 맥락에선 출하검사가 검사기록 3분류(수입/공정/출하)로 이미 흡수 가능 — 출하 '수량' 기록만 추가 검토 |
| ⑤ 설비 마스터(+비가동/금형) | JNKC 설비·금형·비가동 3축, 수준확인 '설비관리' 범주. 이카운트·SystemEver엔 없음(2/3 부재) | 선택. 교집합 아님. 우리는 설비PM·금형점검을 '의무(할 일)'로 이미 커버 — MES식 가동률 집계는 중간2 영역 |
| (참고) 생산계획 | 이카운트·SystemEver 있음, JNKC는 '계획대비실적'만 | 선택. SME 실무는 주간 엑셀 계획이 다수. 작업지시가 있으면 약식 계획은 지시 묶음으로 표현 가능 |

**마스터 5종 자체의 검증**: 공정/품목/BOM/라우팅/거래처는 JNKC 기준정보 14종의 핵심부와 정확히 일치(공정/창고, 품목, BOM, 라우팅, 거래처). 시장이 추가로 갖는 마스터는 작업자, 불량유형, 설비, 창고 — 이 중 **불량유형**만 필수 보완(③), 작업자는 우리 persons가 이미 있음.

**한 줄 결론**: "마스터 5(+불량유형) / 기록 3 + **작업지시** + **자재 입고·투입** + LOT"이 시장 최소 공통분모의 정확한 모습. 즉 가설 ⓐ는 기록 축에서 지시·자재 2개를 과소평가했다.

## 5. 가설 ⓑ 판정 — 데이터→개인/팀 TODO 자동 변환·배정 기능

**판정: 국내 SME MES/ERP 범위에서는 가설 성립(해당 기능을 가진 제품 확인되지 않음 — 전부 현황판·알림 수준). 단, 글로벌 인접 카테고리에 정면 반례 1건(L2L), 국내에 개념 제안 1건(아이워드솔루션)이 존재하므로 "세계 최초"류 표현은 금지, "국내 SME MES에 없는 계층"으로 표현할 것.**

### 5-2. 업계 스스로 공백을 인정한 증거 (가설 ⓑ의 강한 방증)

- [헬로티 SPECIAL REPORT (2020-10-28): "MES 실패 요인은 데이터 업무만 전산화…성공 위해선 TO DO 연계 확장형 MES 구축해야"](https://www.hellot.net/mobile/article.html?no=54811)
  - 요지: MES 도입 후 실패율이 높은 핵심 원인은 "IT 회사는 **행동 업무는 제외하고 데이터 업무만** 모듈별로 전산화"하기 때문. 데이터는 쌓이는데 그 데이터가 요구하는 행동(조사·판단·조치)이 관리되지 않아 결국 입력도 무너진다는 진단.
  - 이는 우리 가설 ⓑ의 문제의식("수집 데이터→사람 할 일 변환이 없다")을 업계 강연이 그대로 언급한 것.

### 5-3. 유사/반례 제품 (정직한 기재)

| 제품 | 국가/카테고리 | 형태 | 판정 |
|---|---|---|---|

### 5-4. 차별점 문장 (권장 표현)

> "국내 중소기업용 MES는 데이터를 **모아서 보여주는 것**(현황판·알림)까지만 한다. 수집된 데이터가 **누가 오늘 무엇을 해야 하는지**(개인/팀 할 일 생성·배정·완료 추적)로 변환되는 계층은 국내 SME MES 제품에서 확인되지 않았고, 업계 스스로 이 공백을 MES 실패의 주원인으로 지목한 바 있다(헬로티 2020). 글로벌에는 이 계층만 파는 별도 카테고리(Connected Workforce, 예: L2L)가 있을 만큼 실재하는 수요다. 우리는 그 계층을 MES 최소 공통분모(§4)와 한 몸으로 제공한다."

- 표준 모델 관점 보강: MESA-11의 11개 분류에도 '데이터→개인 업무 변환'은 독립 분류로 없음(§3-3). 가장 가까운 Dispatching은 설비/라인 단위 오더 분배로, 사람 단위 TODO와 다름.

## 부록 — 조사 한계

- 수준확인제 44개 항목의 **항목별 원문 전문**은 공개 웹에서 확보 못 함(확인기관 배포 자료·자가진단표 다운로드 필요) → 영역·범주·배점·등급 구간까지만 확정 기재.
- JNKC MES는 모듈 목록 전량 공개로 표본 가치가 크나 **가격 비공개**. 엠아이큐브·일원IT·티제이에스는 상세 확인 불가(비공개 또는 사이트 인증서 오류).
- 가설 ⓑ는 "확인된 범위 내 부재" 판정임. 국내 MES 공급기업은 수백 개(스마트공장 보급사업 공급기업 풀)로 전수조사는 불가능 — 단, 대표 제품군·업계 기사·표준 모델 3축이 같은 방향을 가리키므로 판정 신뢰도는 높음.
