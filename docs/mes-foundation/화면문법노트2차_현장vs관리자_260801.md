# 현장 화면 문법 노트 2차 — 현장용 / 관리자용 분리 (2026-08-01)

> **원천**: `TPC MES 설계서 모음` 중 ★1 현행업무분석서 · ★2 요구사항정의서 · ★4 개선업무설계서 ·
> ★12 SF-TI3 매뉴얼(실물 운영 화면). 1차 노트(260726)는 ★6 화면설계서만 봤다.
> **목적**: "관리자가 쓰는 프로그램 / 현장에서 쉽고 간편하게 실행·저장하는 프로그램"의 실제 문법 확보.
> **성격**: 판독 결과. 채택 여부는 별건.

## §0. 최상위 발견 — MES는 애초에 **프로그램이 둘**이다

★12 매뉴얼 p.3 소프트웨어 설치 현황:

```
1  MES 프로그램   MES 관리자 프로그램   1
2                 MES 현장 프로그램     1
```

한 프로그램의 권한 분기가 아니라 **별도 실행 파일 2개**다. 배포도 따로다 —
`http://118.45.229.104` 접속 → "관리자용, 현장용 프로그램을 클릭" → 설치·자동 버전 업데이트.

우리는 한 앱 안에 화면만 나눠 뒀다. **현장 사람이 우리 앱을 열면 관리자 화면이 먼저 보인다.**
"MES 같지 않다"는 인상의 뿌리가 여기일 수 있다.

## §1. 현장 하드웨어 — 추정하지 않아도 된다 (★1 p.6, ★12 p.3)

| 장비 | 수량 | 배치 |
|---|---|---|
| **키오스크** | **14** | 사무실 3 · 가공반 3 · 로브레이징반 4 |
| **TV** | **6** | 사무실 1 · 가공반 1 · 검사반 2 |
| 태블릿 | 8 | — |
| 유선 스캐너 | 7 | 가공반 3 · 로브레이징반 4 |
| 무선 스캐너 | 5 | 사무실 2 · 검사반 2 |
| **트랙볼 키보드** | **7** | 가공반 3 · 로브레이징반 4 |
| 바코드 프린터 | 11 | 사무실 2 · 로브레이징반 3 |
| Mini PC | 5 · 서버 2 · 리크테스트기 4 | |

읽는 법:

- **키오스크 = 서서 터치.** 현장 단말은 앉아 쓰는 PC가 아니다. 3초 룰·큰 타일이 여기서 나온다.
- **트랙볼 키보드 7대가 정확히 키오스크가 있는 반(가공·로브레이징)에만 있다** — 장갑 낀 손은
  마우스를 못 쓴다. 작은 클릭 타깃·드래그·호버는 현장에서 성립하지 않는다.
- **유선 스캐너는 반에 고정, 무선은 사무실·검사반.** 현장 입력의 기본 동작은 타이핑이 아니라 스캔이다.
- **TV 6대가 이미 깔려 있다.** P2 `/tv` 전광판은 하드웨어를 새로 살 필요가 없다 —
  단, 사무실·가공반·검사반에 있으므로 **한 화면이 아니라 자리별로 다른 화면**이어야 한다.

## §2. 관리자 프로그램 문법 — 8버튼 + 색 계약 (★12 §4 공통사항)

**툴바 8개가 전 화면 동일 순서로 고정**:

```
초기화 · 조회 · 추가 · 저장 · 삭제 · 엑셀 · 출력 · 닫기
```

**색이 계약이다** (문서에 명문화):

| 표시 | 뜻 |
|---|---|
| **빨간색 컬럼** | 필수 입력 + **수정 불가** |
| **파란색 컬럼** | 필수 입력 + 수정 가능 |
| 행 표시 + **파란 글씨** | 수정된 행 |
| **빨간 글씨** 행 | 삭제 예정 행 |

**조회 조건은 외우지 않고 고른다**: 거래처·품번 조회조건이 파란색으로 표시되고,
**더블클릭하면 등록된 리스트 창**이 떠서 선택한다.

**그리고 화면 15개가 전부 같은 그리드다.** 개발품번관리·검사기준등록·제품견적서·지그스펙·
원가분석·BOM·개발계획서·최종보고서·개발문서·SPC검사스펙·금형마스터·금형BOM·금형수리이력 —
매뉴얼 설명이 글자 단위로 동일하다. 관리자 프로그램은 **그리드 한 장을 15번 반복**한 것이다.

## §3. 현장 프로그램 문법 — 버튼이 1~2개뿐이다

같은 매뉴얼에서 현장 화면 3종만 설명이 다르다:

| 화면 | 버튼 |
|---|---|
| 16. 실적현황모니터링 | **조회** 만 |
| 17. 공정패트롤검사 | **조회 · 저장** |
| 18. SPC자주검사 | **조회 · 저장** |

추가·삭제·엑셀·출력·닫기가 **없다**.

> **현장에서 하는 일은 둘뿐이다 — 보는 것(조회)과 남기는 것(저장).**
> 현장용은 관리자용의 축소판이 아니라, 버튼을 걷어낸 다른 물건이다.

이 대비가 1차 노트(§1 큰 타일·스캔 우선·우측 액션 패널)보다 더 근본적이다.
1차는 "현장 화면은 이렇게 생겼다"였고, 2차는 **"현장 화면에는 이것만 있다"** 이다.

## §4. 사장님이 1년간 요구한 것 (★2 요구사항정의서 10건)

2024 고도화 사업 요구사항 **10건 중 9건의 업무 담당자 서명이 「하헌」**(나머지 1건 박진희).
회의록 출처 날짜가 2024-10-08 ~ 2024-12-17로 찍혀 있다. **회의에서 나온 말의 원본이다.**

| 유형 | 건수 | 내용 |
|---|---|---|
| **조회 조건 추가** | 3 | 작업장 / 공정구분+작업장 / 입고처+S/LOT |
| **컬럼 추가** | 3 | 증가수량·수집값 / 월 지표·월 누계 실적 / 실적 수집 수량 |
| **컬럼 사이즈 수정** | 3 | 품번 / 품번·품명 / 품번·품명 |
| 콤보박스·Merge 개선 | 2 | KPI 기준정보 / KPI 전략과제 |

**새 기능 요구가 0건이다.** 전부 "기존 화면에서 이걸 더 보여달라"다. §2에서 본 대로 화면 구조가
전부 같은 그리드이니, 사용자가 요구할 수 있는 것이 컬럼밖에 없었다.

짚을 것 둘:

1. **품번·품명 컬럼 사이즈 요구가 3건**이다. 1년간 반복해서 "품번·품명이 안 보인다"고 요구했다.
   그런데 우리 `item_master` 는 **품명 보유 0.0%** 다(A1 대사표 §5). 같은 통증의 더 심한 판이다.
2. **KPI 요구가 3건**이다. 사장님은 KPI를 실제로 쓴다. ★4가 AS-IS를 "엑셀·수기 등록 → 오기입,
   복잡한 구조, 업무 효율 저하"로 적었다. 26번 리포트 A5(KPI 수치 확정)가 여기에 그대로 얹힌다.

## §7. 우리 화면에 대한 함의 (판단 재료 — 채택은 별건)

1. **현장/관리자 분리를 화면 권한이 아니라 진입 자체로 나눌지** 결정이 필요하다.
   MES는 실행 파일을 나눴다. 우리는 최소한 **현장 모드 진입점**을 따로 둘 수 있다.
2. **현장 화면에는 버튼이 2개여야 한다** — 보기·남기기. 지금 우리 양식 작성 화면의
   버튼 수는 현장 문법과 거리가 멀다(관리자 문법에 가깝다).
3. **트랙볼·장갑 전제**: 호버로만 드러나는 것, 작은 ✕, 드래그는 현장에서 못 쓴다.
   (오늘 만든 최근 양식 칩의 ✕가 hover 노출인데, 현장 화면에 쓰려면 상시 노출로 바꿔야 한다.)
4. **TV 6대가 자리별로 다르다** — `/tv` 는 한 화면이 아니라 **사무실용·가공반용·검사반용**이다.
5. **8버튼 툴바 순서**는 관리자 화면 한정으로 채택할 가치가 있다. 현장 화면에 가져오면 안 된다.
6. **색 계약(빨강=수정불가·파랑=수정가능)** 은 이미 우리 `fillable` 배경과 개념이 같다.
   용어만 맞추면 현장 사람이 학습 없이 읽는다.
