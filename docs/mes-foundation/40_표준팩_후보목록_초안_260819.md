# 40호 — 표준팩 후보 목록 초안 (39호 ④ 별도 협의분 · 2026-08-19, 봇)

- 근거: 39호 도장(8/18) ④ "표준팩 내용 = 별도 협의 — 봇이 후보 목록 초안 상신" · ⑤ S1+S4 완결 후 병행.
- 성격: **상품 판단 자료**입니다. 봇은 실측·분류·권고까지만 하고, 편입/제외는 사장님 판정입니다.
- 실측 대상: 복사본 DB(qms-e2e-260818, 0144 적용) 전 테이블 + 마이그 144개 + `resources/` 자산.

## 0. 한 줄 결론

**표준팩의 뼈대는 이미 있습니다.** SQ Ver4 백본(42항목·1000점)·SQ 미니멀 팩(45양식)·IATF 조항·AIAG 코어툴 구조·
KPI 35종·정기의무 표준 27건이 **실명 0·회사명 0**으로 들어 있고, 8/4 시드분리 규칙 이후 마이그 19개가 이미
`[TPC팩 후보]` 태그를 달고 있습니다. 결정이 필요한 것은 **양식 카탈로그·레이아웃(TPC 원본 파생)을 제품 표준으로
채택할 것인가**(④-1·④-2)와 **일상업무 의무 35건·SQ 가이드 예시를 어디까지 중립화할 것인가**(④-3·④-4)입니다.
규정 본문(622섹션)은 표준팩에 넣지 않는 것을 권고합니다 — TPC 실무 규정이고 클린 설치 RED(478행)의 주범입니다.

### 2-D. 코어 (데이터 없음)

마이그 143개 실측 = **스키마 전용 33 · INSERT 시드 84 · UPDATE/DELETE 정정 26**. 운영 로그 테이블(`form_change_log` 129행)은 설치 시 0.

⚠ S2 설계 유의: 0058 이전 혼합 마이그는 파일 단위 스킵이 불가 → "파일 내 DML 건너뛰기" 또는 코어 스키마 통합본(`0000_core_schema`) 신설 중 택1 — S2 착수 시 상신.

## 3. 봇 권고 구성안 — 두 팩

33호 상품 구조(기본판 = 미니MES + SQ 내장 · IATF = 라이선스 애드온)에 맞춰 **표준팩을 둘로** 둡니다.

| 팩 | 내용 | 규모 |
|---|---|---|
| **표준팩-SQ(기본 동봉)** | SQ 백본 42항목 + 가이드층(중립화) + 미니멀 팩 45양식(카탈로그+빈 틀 xlsx) + KPI 35(값 없음) + 정기의무 표준 27(역할 기반) + 코어툴 구조 | 마이그 ~10개분 |
| **표준팩-IATF(애드온)** | IATF 조항 카탈로그 + 문서 BOM 목록 뼈대(105 제목·본문 없음) + 갭 팩 + 내부심사 양식 4종(sq_gap 17~20) + 프로세스 **틀**(9종 제목·페이지 구조만) | 마이그 ~4개분 |
| (고객사팩) | 회사 프로파일·규정 본문·인원·품번·MES 코드·실무 예시 — TPC팩은 현 자산 이관 | 마이그 ~60개분 |

빈 상태로 두는 것: 규정 본문(제목만)·인원(관리자 1계정)·품번·MES 코드·양식 예시·의무 assignee.
→ 설치 첫날 화면이 "우리 회사 이름 + 빈 목록 + 할 일(설정 마법사)"로 뜨는 것이 목표.
