## 4. 수정 요청 소견

### 소견 A 【중요 — PB2 착수 전 수정 권고】 실사진 반입 후 렌더러 프리즈
3MB급 실사진 반입 후 수집함 진입·저장·목록 조작에서 **렌더러 10~45초+ 프리즈 반복**
(검수 중 6회 이상, 1회는 탭 폐기 필요). E2E는 512B 더미라 미검출 — 실물 검수를 남긴 이유가
정확히 이것. 추정: captureImage data URL로 원본급 로드 or 목록 로드 시 이미지 일괄 수신.
확인 요청: ① 업로드 다운스케일(긴변 2000px)이 file input 경로에서도 적용되는지
② 뷰어/목록이 원본을 받는지 ③ 목록은 썸네일 분리 필요성. **현장 폰 UX에 치명 — G1 검수 후속 1순위.**

### 소견 B 【판정 사안】 T4 소급 태깅 = 즉시 "연체 N일"
07-28 전표를 08-05에 태깅하니 발행 즉시 "연체 8일". 전표일 기준이라 정직하지만, 도입 초기
과거 전표 소급 태깅 시 연체 폭탄. "당일 기입 의무" 기준일을 태깅일로 할지 전표일로 할지 사장님 판정 필요.

### 소견 C 【기준정보】 전표 표기 ≠ 마스터 코드
- 입고3 인쇄 품번 45264-3D900-**O2** · 28237-2MAA1-**P1** — 마스터 부재 → 사장님 재가로
  기본형(45264-3D900 · 28237-2MAA1) 태깅 + 비고에 원표기 기록.
- 입고1 수기 접미(B1?·Q1?·B2?·K1?) — 마스터 교차 추정(-D1·-Q1·-C1·-D1·-R1)으로 태깅 + 비고 기록.
  **틀렸을 경우 취소+재등록 정정 대상.**
- 시사점: M4 판독 계약에 "전표 표기 ↔ 마스터 별칭 매핑" 축적 구조 필요(입고3 같은 인쇄 전표도 어긋남).

### 소견 D 【경미】 거래처 자동완성 UX
placeholder "코드 입력·선택"인데 datalist 표시는 이름 — 이름 타이핑 후 저장하면 거부됨.
datalist 선택 시 코드 치환 여부 확인, 미치환이면 이름→코드 해석 허용 검토.

### 소견 E 【경미】 입고 구분 자동 초안 미작동(관측)
거래처 입력 후에도 구분이 "선택"으로 남음(3건 모두 수동 선택). 프로그램적 입력의 이벤트 차이일 수
있으나, change 이벤트 기준 초안 로직 확인 요망. (참고: 세일에스앤티·SW테크·휴먼테크 모두
유형 "(고객)"인데 실거래는 외주 왕복 — 유형→구분 초안 규칙도 함께 점검.)
