## 4. ✅ HTTPS (폰 카메라 전제)

**왜 CA 방식인가**: 폰 브라우저는 "자체 서명 leaf" 를 신뢰 목록에 못 넣는다. 신뢰는 CA 단위다.
→ 사내 루트 CA 1회 발급 → 폰에 CA 1회 설치 → 그 CA 로 서버 인증서 서명. 서버 IP 가 바뀌어도 leaf 만 재발급.

- 신설 `scripts/gen-tls-cert.mjs` — openssl 자동 탐색(PATH → Git for Windows 동봉본, 별도 설치 불필요).
  산출 = `%APPDATA%\iatf16949-manager\certs\` (repo 밖 — **개인키가 git 에 절대 안 들어간다**).
- SAN = `localhost` · `DESKTOP-LH2GCO1` · `127.0.0.1` · `192.168.4.25` · 유효 825일.
- `server/index.cjs` — `IATF_TLS_CERT` + `IATF_TLS_KEY` 가 **둘 다** 주어질 때만 HTTPS. 미지정이면 종전 HTTP 그대로
  (기존 기동 스크립트·E2E 하네스 전부 무영향). 한쪽만 주거나 파일이 없으면 **HTTP 로 조용히 내려가지 않고 즉시 중단**(35호 무음 실패 금지).
- ⚠ 바인딩은 이 변경과 무관하게 `127.0.0.1` 고정 유지 — 사내망 개방은 별도 도장 사안이다.

**검증**: 임시 클린 설치 `:8443` 기동 → 사내 CA 로 `127.0.0.1` · `localhost` · PC이름 · `192.168.4.25`
**4개 이름 전부 인증서 신뢰 = true · HTTP 200**. 평문 HTTP 접근은 거부됨. 검증 후 임시 서버·DB 정리.

> curl 로는 실패로 보였는데, 이는 윈도우 curl 의 schannel 백엔드가 사내 CA 의 폐기목록(CRL)을 못 찾아 거부한 것이지
> 서버 문제가 아니다. OpenSSL 기반(Node)으로 재검증해 통과 확인.

웹 셸에는 dialog 가 없다.** 이 방식이면 데스크톱·웹이 한 경로로 동작한다.

### 저장
`userData/branding/logo.<확장자>` (웹에서는 `IATF_DATA_DIR` 아래). DB 밖에 두는 이유 = xlsx 삽입이 파일을 요구하고,
