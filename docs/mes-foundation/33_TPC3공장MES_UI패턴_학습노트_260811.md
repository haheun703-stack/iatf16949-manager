## §2 추출한 문법 (데일리Q 적용분)

1. **화면 3형 체계** — ① 모듈 홈 = KPI 카드 + 추이 차트(카드류는 여기에만) ② 관리 화면 = 필터바 + CRUD 그리드 ③ 현황 화면 = 필터 + 조회 그리드 + 인쇄/엑셀. 32호 §1-5("카드·도넛류는 조회 화면에 두지 않는다")와 정확히 일치.
2. **모듈 홈 층의 존재** — 65장 정본에서 못 봤던 층. 1차 메뉴 진입 시 그리드가 아니라 KPI 대시보드가 먼저 나온다. → 데일리Q도 1차 메뉴별 메인화면 = KPI 카드 4 + 차트 2 표준.
3. **그리드 색상 코딩** — 문서/발주번호=빨강, 품명=파랑 링크(+아래 품번 첨자), 금액=주황, 수량=파랑. 32호 §7-① 진한 파스텔 단계로 재해석해 적용.
4. **MY MENU 즐겨찾기** — 좌측 고정, 사용자가 화면을 핀. 32호 §1-2 즐겨찾기와 일치.
5. **전 화면 엑셀 내보내기 표준 탑재** — 현황·관리 불문.

## §3 채택하지 않는 것

- 데스크톱 고정폭 프레임(우리는 모바일 퍼스트 유지 — 현장 입력은 모바일, 조회·관리는 데스크톱 문법)
- 광고 배너(라벨지 견적)·고객센터 카드·구식 팝업 검색창
- 디자인 원색 복제 — 상용 제품이므로 **타입(골격)만 참고**, 색·아이콘은 우리 파스텔 토큰으로.

## §4 상품 구조 방향 (사장님 8/11 구두 + 봇 동의)

- **기본판** = 미니MES(무른모 타입 골격) + **SQ 심사 항목 내장** — 심사대응 메뉴의 SQ부는 기본 탑재.
- **IATF16949 = +@ 판매 애드온** — 심사대응(SQ/IATF) 메뉴 안에서 IATF 뷰·문서BOM·조항 매핑 열을 **라이선스 플래그 1개로 잠금/언락**. 별도 앱·별도 DB 아님.
- **불변 조건**: 기록→요구항목 매핑 테이블은 처음부터 {SQ 항목번호, IATF 조항} 2열 겸용 설계. 애드온은 화면·라이선스 층이지 데이터 모델 층이 아니다.
