## 3. 경계안 (제안)

### 3층 분리

| 층 | 내용 | 배포 |
|---|---|---|
| **코어** | 스키마 + 엔진 + 화면. **회사를 모른다.** | 전 고객 공통 |
| **표준팩** | 업종 무관 기본 골격(양식 뼈대·의무 템플릿·코드) — 실명 0·회사명 0 | 기본 동봉 |
| **고객사팩** | 회사 프로파일 + 실무 데이터. `TPC팩` 은 그중 하나(현 자산 이관) | 고객별 |

### 이행 방식 — 과거를 건드리지 않는다

- 기존 마이그 142개는 **그대로 둔다**(라이브 호환 유지).
- **신규 설치 경로를 새로 만든다**: `스키마 마이그만 적용` → `선택 팩 적용`.
  현행 데이터 시드 마이그는 **`TPC팩`으로 태깅**해 신규 설치에서 건너뛴다.
- **회사 프로파일 외부화**: `app_config` 에 회사명·사업부·공정·문서번호 체계를 두고,
  축① 10곳이 전부 그 값을 읽게 한다(하드코딩 0).
- **실명 제거**: 표준팩 시드는 역할 기반('품질팀장')이거나 **빈 상태**. 실명은 설치 후 사용자 등록.
- **검증 신설**: 빈 DB → 설치 → **"우리 회사" 이름으로 뜨는지** + TPC 문자열·실명 **0건** 자동 단언
  (`e2e-clean-install.mjs` — 판매판 회귀에 상설 편입).

### 견적 (개략)

| 단계 | 내용 | 규모 |
|---|---|---|
| S1 | 회사 프로파일 외부화 + 축① 10곳 배선 | 반나절 |
| S2 | 마이그 팩 태깅 + 신규 설치 경로 분기 | 1~2일 |
| S3 | 표준팩 골격 설계·시드(양식 뼈대·의무 템플릿) | **2~3일**(내용 판단 필요) |
| S4 | 클린 설치 검증 하네스 + 판매판 회귀 | 반나절 |

S3 이 가장 큽니다 — "표준팩에 무엇을 넣을 것인가"는 기술이 아니라 **상품 판단**입니다.
