## 사고 ① 라이브 재기동 무음 실패 (구판 계속 서빙)

- **경과**: 35호 재검 합격 후 라이브 재기동 시도 → 코워크 실측 tvBoard 404(구판 그대로).
  구판 프로세스(아침 7:51 자동 시작분)가 :8080 점유 중이면 런처(start-qms-web.vbs)는
  설계상 "살아 있으면 브라우저만 연다" — 재기동이 아니라 **구판 접속**이 된다.
- **2차 발견**: 서버 콘솔 창을 닫아도 프로세스가 안 죽는다 — electron.exe 는 GUI 계열이라
  **콘솔에 부착되지 않는다**. "Close this window to stop" 안내가 애초에 틀린 전제였다.
- **재발 방지(커밋 597fa75)**:
  1. `start-qms-server.bat` — 기동 전 포트 점유 감지 → [FAIL] 창 잔류 + 안내(무음 실패 금지).
     자체 종료 시에도 로그 꼬리 15줄 + 창 유지.
  2. `start-qms-web.vbs`·`start-qms-server-silent.vbs` — 기동 대기 실패 시 MsgBox(빈 브라우저
     열지 않음).
  3. **`restart-qms-server.bat` 신설 = 재기동 정본**: 구판 kill → 신판 최소화 기동 → health
     확인까지 원클릭(재로그인 1회 고지). **창 닫기로 재기동하지 말 것.**
- **판별법**: 로그인 후 `semimes:tvBoard` 호출 — 404 = 구판 · 200 = 신판(0141+ 세대 기준).

## 사고 ② E2E 잔여물을 "라이브 실사용"으로 오인

- **경과**: 검수 회신의 "오늘 실사용 증가 — 생산 6건(양품 589)·검사 4건·2단 확인 대기 4건·
  수불 4건·실지시 WO-260813-01~03" — 전량 **:8081 복사본의 E2E 잔여물**로 판명.
  - 검산: 활성 생산 6건 = 50+50+130+70+239+50 = **정확히 589**(pc1 회귀 2회×50 + 전광판
    픽스처 130·70·239·50).
  - WO-260813-01·02·03 생성 시각 = E2E 실행 시각과 초 단위 일치, 같은 초에 'E2E-VLOT-1'
    입고 전표 동반(g1 픽스처).
  - **라이브(:8080) 오늘 기록 = 전 축 0건**(지시·생산·검사·입고·LOT·수집함·양식 — 실측).
    실기록 손실 없음. 이관 불요.
- **오인의 뿌리**: pc1 등 E2E 가 **서규하 계정으로 로그인** → STAMP(작성자·작업자·검사자)가
  '서규하'로 각인 → 사람 기록과 화면상 구분 불가.
- **재발 방지 규약**:
  1. **검수 복사본(:8081)의 건수·통계는 실사용 근거로 쓰지 않는다** — 실사용 판독은 반드시
     라이브 DB 기준.
  2. 파생 판단 철회: "2단 확인 대기 4건 → 확인자 서명 현장 공지 검토"는 근거 소멸(대기 4건
     = E2E 잔여물). 실제 공지 필요성은 실사용 발생 후 재판단.
  3. **후속(소규모, W4 편승 후보)**: ⑴ E2E 전용 계정('E2E봇') 복사본 시드 — STAMP 가 사람과
     절대 안 섞이게 ⑵ 검수 서버 화면 상단 "검수 복사본 — 실기록 입력 금지" 표지(서버 플래그).
  4. 검수 종료 시 :8081 은 내린다(오입력·오인 창 자체를 없앰) — 필요 시 새 복사본으로 재기동.
- **보존**: 오늘 복사본은 `_DB백업_260801/실기록보존_8081복사본_260813/`(원본+WAL 반영판)
  으로 박제 — 잔여물뿐임이 확정됐으므로 참고용.
