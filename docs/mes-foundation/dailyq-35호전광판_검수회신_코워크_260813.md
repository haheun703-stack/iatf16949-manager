## 2. Major 1건 — 갱신 폭주 (60초 계약 위반)

- **실측**: 전광판 표시 중 `semimes:tvBoard` POST **10초에 1,000건+ (초당 100건 이상, 전부 200)** — 60초 폴링이 아니라 연속 재발사. 관찰 3회 재현(로그 상한 1,000건 반복 도달).
- 화면 자체는 정상 동작(갱신 시각 진행·데이터 표시)이라 육안으로는 안 보이는 결함 — 전광판은 하루 종일 켜두는 화면이므로 서버가 상시 초당 100회 얻어맞는 구조. **TV 설치 첫날 = 서버 과부하 사고 예약**.
- **ESC 복귀 시 폭주 즉시 정지(8초간 0건)** — unmount 정리는 정상. 원인은 마운트 중 재발사 루프(의심: useEffect 의존성에 매 렌더 재생성 객체 → fetch→setState→재렌더→재fetch).
- E2E가 못 잡은 이유 = 채널 직호출이라 렌더러 폴링 루프 미경유. **재발 방지 요구**: 재봉합에 렌더러 폴링 계수 검증 추가(짧은 마운트 창에서 요청 수 ≤ 기대치 단언) 또는 perfWatch에 채널별 호출률 마크 — 이번 결함이 perfWatch 관측에도 안 걸렸다는 점 포함해 보강.

## 3. 판정 ③(라이브 재기동 창) — 권고

- **재봉합 후 한 번에**: 어차피 tvBoard 채널 노출에 재기동이 필요하므로, 폭주 수정판까지 묶어 **재기동 1회로 처리** 권고. 현재 라이브는 [TV현황판] 클릭 시 "통신 오류" 배너(무해)뿐이니 급하지 않음 — 점심 창이면 충분.
