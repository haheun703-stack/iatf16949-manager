## 1. B′ 처분 내역

### N-2 — 사용자 관리 무통지 5동선 (Major)

C-1 로 `appUser` 쓰기 3종이 executive 전용이 되면서 **부서·역할·활성·등록·삭제**가 전부
"눌러도 아무 일 없음"이 됐던 자리. 4갈래로 처분:

| 지적 | 처분 |
|---|---|
| ① 모달 진입 role 게이트 없음 | **표시 전용 전환** — 비 executive 는 배너 + 전 컨트롤 잠금(이름 목록 열람은 스위처에도 이미 보이므로 화면 자체는 막지 않음) |
| ② 비exec 화면에서 편집 UI 활성 | **신규 추가 영역 미표출** · 행 `select` 전량 `disabled` · 이름 `readOnly` · 버튼 3종 `disabled`+"최종관리자 전용" 표기 |
| ③ 403 을 store `catch{}` 가 삼킴 | `activeUserStore.upsertUser/deleteUser` 반환형을 `boolean/void` → **`WriteResult{ok,error}`** 로. 실패 사유를 호출부까지 올리고 **`invokeErrText` 경유**(신규 쓰기 화면 규약) |
| ④ "이미 있는 이름" 오안내 | 서버가 사유를 주면 **그게 정본**, 없을 때만 이름 충돌 가능성을 언급하도록 문구 재작성. 실패 시 입력값도 지우지 않음(재시도 가능) |

### N-7 — M-11 가드가 로컬 role 을 신뢰 (Major)

`AppShell.isExec` 가 `activeUserId`(= localStorage, 비번 없이 아무나 변경) 기반이라
**스위처 클릭 1회로 매트릭스 열람**이 됐던 자리.

- `activeUserStore` 에 **`session`(= `/api/auth:me` 서버 세션)** + `sessionChecked` 신설.
  세션 조회를 **목록 로드보다 먼저** 확정(목록이 실패해도 권한 판정은 남아야 하고, `sessionChecked`
  가 영원히 false 로 남던 구멍도 같이 닫힘).
- `AppShell.isExec` → 세션 role 정본. **판정 전에는 거부 화면 대신 "권한 확인 중…"**(가짜 거부 깜빡임 방지).

  가드만 고치면 메뉴는 뜨는데 눌러야 거부되는 오안내가 남습니다.
- **한계 고지(정직 표기)**: 데스크톱은 세션 개념이 없어 로컬 판정 유지. 그 축은 서버 강제도
  자기신고라 여기서 못 닫습니다(**N-9 · Minor 4 잔존** — 화면에도 그대로 적었습니다).
