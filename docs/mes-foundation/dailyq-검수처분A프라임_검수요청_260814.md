## 1. N-1 — sq:assessExport 의 라이브 DB 경로 각인 차단

웹 모드의 저장 경로는 서버가 주입한 **임시 토큰 경로**(다운로드 1회 or 30분 TTL 후 삭제)인데
`report_path` 에 그대로 UPDATE 하고 있었습니다. 데스크톱이 남긴 정상 경로까지 덮어씁니다.

- `electron-shim.cjs` 에 **웹 표식 `__webShim`** 신설 — 핸들러가 데스크톱/웹을 구분할 유일 근거
  (실제 Electron 의 `app` 엔 없는 속성).
- `sq-report-exporter.ts` — `isWebRuntime()` 이면 UPDATE **건너뜀**. 웹은 사용자 PC 의 저장
  위치를 서버가 알 수 없으므로 **미갱신이 정직한 상태**(화면은 값이 있을 때만 "리포트: …" 표시).
- **실증 설계**: 데스크톱이 남긴 것처럼 정상 경로를 미리 심어둔 뒤 웹 내보내기 1회 →
  값 **무변경** 확인. 구판이면 이 자리에서 임시 경로로 덮여 있었습니다.

## 2. N-12 — (신규 발견) 웹 SQ 리포트 내보내기 전면 불능 + **제 판정 정정**

N-1 실증 중 나온 사실입니다. **shim 의 `getAppPath()` 가 한 칸 어긋나 있었습니다.**

- `join(__dirname, '..')` 인데 번들 후 `__dirname` 이 `server/dist` 라 → `<root>/server`
  → 소비처가 `<root>/server/resources/…` 를 봅니다(**존재하지 않는 폴더**).
- 소비처는 `app.getAppPath()` 를 쓰는 `sq-report-exporter` **단 1곳**(`form-export-engine` 등
  나머지는 `__dirname` 상대라 정상). 그래서 **웹 SQ 자체평가 리포트 내보내기 = 항상
  "템플릿 없음" 실패**였습니다(어제 M-1 소생으로 이 지점에 *도달*하게 되면서 드러남).
- 처분: 번들 위치에 의존하지 않도록 `resources/migrations` 를 품은 조상 폴더를 찾아 올라가는
  방식으로 앱 루트 확정(못 찾으면 종전 동작 보존).

> **⚠자기정정(8/14 검수 §5 에 4번째로 추가)** — 제 검수의 **"N-1 은 재기동하는 순간부터
> 발화"는 과대**였습니다. 실제로는 템플릿 미발견으로 **핸들러가 UPDATE 에 닿기 전에 죽어**
> 라이브 오염이 일어나지 않았을 것입니다. N-1 결함 자체(무가드 UPDATE)는 실재하고 처분도
> 유효하지만, **"재기동 전 필수"의 근거는 제가 잘못 짚었습니다.** 다만 N-12 를 고친 지금은
> 경로가 실제로 열리므로, **두 처분은 같이 나가야 맞습니다**(N-12 만 고치고 N-1 을 두면
> 그때부터 진짜로 발화).
> 실증도 그 순서로 남겼습니다: N-12 수정 **전** = 내보내기 실패·각인 0 → **후** = 내보내기
> **성공(다운로드 토큰 발급)·각인 여전히 0**.

## 3. N-6 — copy 판정 강화 (거짓 안심 제거)

`copy` 는 렌더러의 "검수 복사본" 표지 + **E2E 하네스 게이트**(`lib/e2e.mjs loginBot`)가 믿고
쓰기까지 진행하는 값인데, 종전 판정이 `!!IATF_DATA_DIR`(env 존재 여부)뿐이었습니다.

- 이제 **"env 지정" + "실제로 연 DB 가 라이브 DB 가 아님"** 을 함께 요구합니다.
- 정션·subst 우회 차단 위해 **realpath(native) 실경로 비교 + 동일 파일(dev·ino) 비교** 병행.
- **판별 불능(APPDATA 미설정 등) = copy=false** — fail-closed(하네스 즉시 중단, M-7 과 같은 결).
- **기동 로그 1줄 신설**: `[server] 대상 = 검수 복사본(copy=true)` / `★라이브(copy=false)` —
  health 를 못 보는 재기동 창에서의 오인 방지.
- 실증 3종: ①env 가 라이브 경로 → **copy=false** ②진짜 복사본 → **copy=true**(회귀 없음)
  ③**정션으로 라이브를 가리켜도 copy=false**(종전이라면 true = 거짓 안심).

## 4. N-8 — NULL 비번 계정 선점 제거

`password_hash` 가 NULL 이면 **요청자가 보낸 비번을 그대로 설정**해 로그인시켜 주고 있었습니다.
신설 계정을 **처음 접근한 사람이 선점**해 그 실명으로 STAMP 활동이 가능합니다.

- 이제 **로그인 거부** + 안내: "초기 비밀번호가 발급되지 않은 계정입니다. 관리팀에 발급을
  요청하세요."
- 근거: 관리형 비번 체계(**사장님 7/25** — 관리팀이 4자리 비번 지정·대장 보관)가 정본이 된
  이상 자가 설정 창구는 불필요합니다. 발급 경로는 그대로 살아 있습니다 —
  **일괄** `scripts/setup-passwords.cjs` · **개별** `appUser:resetPassword`.
- **잠금 위험 없음**: 발급이 오프라인 스크립트라 "전원 로그인 불가 → 아무도 못 고침" 교착이
  생기지 않습니다. 라이브 실측 NULL **0명** = 기존 사용자 영향 0.
- 실증: NULL 계정 심고 로그인 시도 → 거부·세션 미발급·**시도 후에도 여전히 NULL**(선점 불가).
