## §0 진단 (코워크 실사, 8/5 라이브 화면 기준)

1. **중복 3겹** — 도넛 7카드 / 기록 커버리지 매트릭스 / 품번×공정 실황이 같은 상태 정보를 3번 표출.
2. **서열 부재** — 오늘 움직여야 할 숫자(데이터 할 일 44건)가 상단 구석 칩에 있고, 죽은 정보(공백 셀)가 화면의 70%를 점유.
3. **이중 항해** — 사이드바 20여 항목 + 상단 7모듈 메뉴 병행.
4. **회색 벽** — "정직한 공백" 원칙이 시각적으로는 "데이터 없음"의 7회 반복으로 나타남.
   원칙은 유지하되 표현을 집약할 것.

> 눈에 보이는 관리의 철칙: **전부 보이게가 아니라, 문제만 크게 보이게.**

## §1 원칙 — 3정5행의 화면 번역 (이후 모든 화면의 준거)

| 5행 | 화면 규칙 |
| --- | --- |
| 정리 | 홈에서 안 쓰는 것 제거 — 조회성 정보는 홈에 두지 않는다 |
| 정돈 | 문제(빨강) → 할 일 → 현황 순. 위에서 아래로 심각도 내림차순 |
| 청소 | 공백·미반입은 반복 표출 금지 — 배너 1줄로 집약 |
| 청결 | 카드 문법 표준화: 카드당 배지 1 + 핵심 숫자 1, 그 이상 금지 |
| 습관 | 매일 아침 같은 위치에서 3질문에 답한다: ①어제 빠진 것 ②오늘 할 것 ③심사까지 위험한 것 |

**3정**: 정품(한 화면 한 목적) · 정량(홈 위젯 ≤ 5개) · 정위치(역할별 홈 — 사장/팀원 분리, 29번 팀별 허브 연동은 PC 단계).

## §2 관제탑 새 구조 — 3층

1. **1층 문제 배너 (조건부)** — 문제가 있을 때만 빨강/주황:
   `⚠ MES 미반입 6일째 · 데이터 할 일 44건(연체 12) · 심사 D-71 미충족 k항목` — 각 항목 클릭 = 해당 화면 직행.
   문제 0이면 초록 한 줄("오늘 기록 정상 진행 중")로 축소.
2. **2층 오늘 할 일 TOP5** — 보드 상위 5건(연체 → 오늘 due → 확인 대기 순), [✓처리]는 기존 규율(✓는 사람) 그대로. 하단 [전체 보드 →].
3. **3층 공정 실황 스트립** — 도넛 7카드 → 높이 1줄(~80px) 미니 칩 7개로 축소. 문제 공정만 색 강조, 정상·미반입은 무채색 소형. 클릭 시 커버리지 매트릭스 상세로 진입.

## §3 이동·숨김 목록 (정리 대상)

| 현재 홈 블록 | 처분 |
| --- | --- |
| 품번×공정 실황 표 | 홈 제거 → 생산관리 메뉴 하위 조회 화면으로 이동 |
| 기록 커버리지 매트릭스 | 홈 제거 → 3층 스트립 클릭 시 2층 상세로 |
| 상단 상태 칩 4종(MES 수신·기준정보·오늘 수신·데이터 할 일) | 1층 문제 배너로 통합(문제 없는 칩은 표출 안 함) |
| 기준정보 집계(품목 2,308…) | 홈 제거 → 기준정보 모듈 첫 화면으로 |

- 제거 = 데이터·채널 삭제 아님. 화면 위치 이동만. **정보 손실 0 확인표**(PB2a 방식) 필수 동봉.

## §4 사이드바 정돈

- 4묶음(심사 대응 / 매일 관리 / APQP·Core Tool / 문서·양식) 유지하되 **기본 접힘**: APQP·Core Tool, 문서·양식.

## §5 정량 가드 (재발 방지 — UI 헌법에 추가)

1. 홈 위젯 ≤ 5. 신규 위젯 추가 시 기존 1개 제거 또는 2층 이동을 같은 커밋에 명시(one-in one-out).
2. 동일 데이터의 화면 내 2회 표출 금지.
3. 카드당 배지 1 + 숫자 1.

## §6 모달 시트 문법 (병행 채택 — 도장 별도 ⑥-1)

- PC = 중앙 모달, 폰 = 풀스크린 시트, 1컴포넌트. 적용 1호 = 수집함 태깅 폼(모달 안 좌사진·우폼 2단).
- 닫기(ESC·바깥 클릭) 시 미저장 입력 있으면 확인 대화. 저장은 명시 버튼만(자동 저장 금지 — ✓는 사람).
- 후속 적용 후보: 보드 [처리]·해소 확인, 확인자 서명, 취소+재등록 사유 입력.
