## 이행 내역 (B-1 → B-2 → B-3)

### B-2 태깅 화면 + 채널 (M1 §2 설계 그대로)

- **화면** = `ReceiptInboxView.tsx`(신규, PageId `receipt-inbox`) — 템플릿 C: 좌 380px 목록
  (탭 = 숫자 밴드 클릭: 미분류·오늘 입고·오늘 출하·전체) + 우 사진 뷰어/태깅 폼.
  사이드바 "입고 사진함(disabled)" 예약석을 실화면으로 교체. 풋터 DB v0101→v0136 갱신.
- 폼 = 유형(입고/출하 정정 가능)·전표일자·거래처(마스터 datalist, 유형 표시)·입고 구분
  (partner_type 초안 자동)·**[품목 행 추가]**(1:N)·업체LOT(공란 허용 명기)·비고(단가·금액 금지 명기).
  미선택 시 = 요약 카드(미분류 n·오래된 미분류 TOP 5 — 규칙④).
- 업로드 = [입고 전표]/[출하 전표] 버튼 2개(M1 §3 1차 판별) → 캔버스 다운스케일(긴 변 2000px·
  JPEG 0.85 — 서버 8MB JSON 한도 안).
- **채널 5종**(semimes-handlers 편승): `captureList`·`captureCreate`·`captureImage`·`captureTag`·
  `itemSearch`. **견적 2~3개 → 실측 5개**(정직 고지): 웹에서 사진 표출은 정적 노출 없이 채널
  (data URL)로 — 서버 파일 라우트 신설 회피가 +1, 품번 검색 경량 채널 분리가 +1.
- 서버 가드 3곳: STAMP(captureCreate·captureTag → createdBy 세션 강제) + REQUIRED(3채널) +
  PROTECTED 무추가(= 로그인만 — form:submissionCreate 등 기존 쓰기 채널과 동일 급. 이견 시 반전).
- 태깅 계약(핸들러 검증): 거래처·품번 마스터 실존 강제 / 수량 > 0 / 업체LOT 공란 허용 /
  **재태깅 거부**(append-only — 정정 = 취소+재등록, 취소 채널은 후속 검수 트랙) /
  출하 = mat_receipt 0행(content 만 — 15번 경계) / content = JSON 명세 v1 그대로(M4 판독 계약).
- INLOTUSE: item_master.inlotuse=1 이고 업체LOT 기입 시에만 internal_lot 승계 — 자체 발번은
  PC 단계 lotIssue 소관(선점 안 함).

### B-3 수입검사 데이터 트리거 (M3 확장 — 신규 엔진 0)
