## 채널 8종 (견적 6종 + 2종 초과 — 정직 고지)

29번 §4 명시 6종: `scanResolve` · `lotIssue`(품번-YYMMDD-차수) · `prodRecordCreate` ·
`inspRecordCreate`(헤더+값 단일 트랜잭션) · `workOrderUpsert` · `todayRecords`.
**+2종 사유**: ⑦`recordCancel` — append-only 정정(사유 필수 취소 마크)이 §4 규칙인데 채널
없이는 규칙이 종이에만 있게 됨 ⑧`inspConfirm` — §10-1 ⓒ "확인자 ✓는 사람"의 실행 채널
(confirmer·confirmed_at 세션 각인). 서버는 가드 맵 3곳 추가 외 무수정(29번 §4 그대로).

## 계약 (도장된 원칙의 코드 번역)

- **append-only**: 기록 UPDATE 채널 없음. 정정 = recordCancel(사유 필수, canceled_* 각인 —
  마이그 0137) + 재입력. 취소된 행은 집계 제외·화면 취소선 표기.
- **실측값 강제**: 검사값 = 수치 필수(○/× 단독 저장 거부). 자동판정은 규격(su/sl) 대조
  **제안만** 반환 — 확정은 사람 탭.
- **§10-1 각인**: inspRecordCreate 가 기록 시점 활성 insp_spec 의 revision 을
  `spec_revision` 스냅샷으로 기입 + `sample_phase`(초품/중품/종품 — 자주검사 필수) 기록.
  confirmer 는 inspConfirm 채널만 기입(대필 경로 0).
- **recordSource**: app_config `semimes.recordSource` — 코드 기본 **'direct'**(판매 기본,
  29번 §1). 'sidecar' 면 쓰기 5종 채널 거부(TPC 계약). ⚠️**판정 요청**: 라이브(TPC)를
  sidecar 로 잠글지 — §8-① 원안은 sidecar 이나 MES 덤프 중단(7/30~) 중이라 direct 가
  실용적. 미설정 시 direct 로 동작하므로 **사장님 판정 후 라이브 키 기입**.
- STAMP: worker·inspector·createdBy·canceledBy·confirmer 전부 서버 세션 강제.

## 화면 3종 (현장 문법 — 문법노트2차 §3)

1. **검사 등록**(현장): 품번/스캔 [조회] → 문맥(품명·라우팅·스펙·최근 LOT) → 초/중/종 탭 ·
   시료별 수치 입력 · 자동판정 제안 표시 → [저장]. 버튼 2개 문법·큰 타깃.
2. **생산실적 등록**(현장): 품번/LOT [조회] → 양품/불량 수량·불량유형·주야 → [저장] →
   "자주검사 초·중·종 기록" 바로가기(3차 노트 실적↔검사 교차).
3. **작업지시관리**(사무실): 그리드 — 지시 목록·상태(대기/진행/완료/취소)·[추가]·[상태 변경].
   관리자 문법(8버튼 중 가동분만·나머지 흐림 정직).

설비점검 등록 예약석 = **L1100-07 양식 직행으로 대체**(전용 스키마가 0101 기록 5종 밖 —
PC-2 검토). 금형 타발수 = 별도 판단 유지(26번 A4).
