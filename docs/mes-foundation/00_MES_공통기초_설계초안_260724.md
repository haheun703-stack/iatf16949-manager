# MES 공통 기초 설계 초안 — 반(半)-MES 층 (v2)

작성: 2026-07-24 · 근거: 사장님 구두 지시(축 반전·사진 우선·공통화) + `1-1 MES 작성자료` **2021·2022·2024 3개년 전수 판독**
상태: **v2.1 — 코워크 6건 결정 반영(7/24 인가)**. 벤치마크 매트릭스 후 코워크가 15번 지시서 정식화.
⏳ 사장님 도장 대기 2건: ①§7 경계 원칙("돈·기계·재고 안 만진다") ②데이터 트리거 할 일의 관제탑 통합 — 이견 없으면 확정.

---

## 1. 배경 — 축 반전

지금 앱은 "심사 양식을 작성하는 도구"이고, 원천 데이터(생산·검사)가 없다.
방향 전환: **원천 데이터 층(반-MES)이 기반, 심사 문서는 그 위의 출력물(SUB)로 강등.**

- 회사는 삼성전자 대·중소 상생형 스마트공장 사업으로 MES를 **3회(2021·2022·2024) 구축** — 설계 산출물이 전량 보존됨(요구사항정의서·기능대비표·화면설계서·**DB설계서**·VOC·완료보고). 이것이 도메인 정답지.
- 목적은 TPC 전용이 아니라 **공통(범용) 기초** — 다양한 중소 부품사 판매가 최종 목표.

## 2. 3개년 진화 사다리 (실측) — 그대로 범용 제품의 온보딩 경로

| 회차 | 본질 | 내용 |
| --- | --- | --- |
| **2021 기초** (SJIT) | **마스터 + 사람 입력(POP)** | 공정 마스터 17행(C10 절단·P10 포밍/축관·K10 코킹·O10 압입·B10 밴딩·Q10 PI'G…), BOM 1,110행(원자재→반제품→완제품), 라우팅 1,323행(품목→공정→순번+외주여부), 트리 91품번. 현장 키오스크: 지시선택→작업시작/종료·불량·투입LOT 등록·라벨 출력 |
| **2022 확장** (SJIT) | **품질검사의 MES화 + 현장 UX** | SPC 자주검사·공정패트롤 전산화(검사SPEC 이미지첨부·초중종 시각 자동표시·**작업자→검사자 자동 등록**·마이너스 키패드·현재 생산품목만 표시), 개발관리(E.O넘버), 금형관리 정교화, 실적현황 모니터링(가동/유휴/계획정지). DB설계서 14테이블 |
| **2024 고도화** (SWIT, 완료보고 2025-07-10) | **설비 자동수집 + 확산** | 조관사업부로 2사업부 확산(MES 서버 2대), **설비 PLC 게더링**(가공수량 33·리크검사 4·조관 7 접점, N/W 공사 4,960만), 검사설비 비상정지 실시간 문자알림, KPI 전산화(MES 연계), SCM(외주 17개사 포털: 발주·라벨발행·수불·재고), 15bar 리크테스터 신설(웨스텍). 총 3.15억(지원 1.5억) |

**사다리 요약: 수기 → ①마스터+사람입력(POP) → ②검사 전산화 → ③설비 자동수집(PLC) → ④외주 확산(SCM).**
범용 고객도 같은 사다리를 오른다. **우리 제품 = ①~② 단을 제공**(경량·소프트웨어만). ③단(PLC 공사)은 하드웨어 영역이라 하지 않는다 — 고객이 ③단이 필요해지면 스마트공장 보급사업(공급기업 동반)으로 넘기고, 우리는 그 위 **품질 증거층**으로 존속한다.

### 2.5 데이터→할 일 변환 = 관제탑 통합 (코워크 결정 #2)

반-MES 데이터 트리거(검사 도래·금형 타발수 한계·부적합 발생·심사 갭)는 **별도 엔진이 아니라 기존 관제탑 의무 체계에 통합** — `trigger_type(periodic|data)` 확장. "오늘 할 일"의 정본은 한 곳뿐이어야 한다. 15번에서 반드시 명세할 **4규칙**(이 설계의 진짜 난제이자 해자):

1. **발행**: 트리거 충족 시 1건, 중복 발행 방지 키
2. **소멸**: 데이터가 트리거를 해소하면 **표시만**, 완료 ✓는 사람이 — "작성기록만이 ✓" 원칙과 정합
3. **취소**: 원천 데이터 정정 시 처리
4. **배정**: 트리거 데이터의 공정/팀 → 담당자 매핑

기존 MES가 "시키지 않는" 이유 = 이 4규칙을 안 풀어서. 우리가 풀면 그것이 차별점.

## 3. 2021 기초 판독 결과 (원본 실측)

원본: `1-1 MES 작성자료/※2021…/0. MES 최신 트리,라우팅-김민수 자료_200715/`

**품목 코드 체계(회사 자생 규칙 — 그대로 표준화 가치 있음):**

- 완제품 = 고객 품번 (`28235-2B740`)
- 반제품 = 품번 + **공정 접미사** (`-C1` 절단, `-P1` 포밍, `-K1` 코킹, `-B1` 밴딩, `-Q1` PI'G, `-T1`/`-R1` 후공정…) → 접미사가 공정 마스터와 호응
- 원자재 = 재질-규격 (`STKM11A-0845-07`)

**핵심 발견**: 앱 BOM 마스터(0006 적재)에 빠져 있던 "품목↔공정 매핑(도메인 입력 필요)"이 바로 이 **라우팅 파일**. 2021년에 이미 만들어져 있었다.

## 4. 공통 마스터 6종 + 기록 5종 (벤치마크 검증 반영 확정판)

범용 스키마 — TPC 데이터는 첫 번째 시드일 뿐, 구조는 고객 무관. 괄호는 2022 실전 스키마(`pop_*`)에서 채택하는 포인트.
★벤치마크 검증([02 매트릭스](02_기능교집합_매트릭스_260724.md)) 보완 3건 반영: **+작업지시**(수준확인 기초 핵심·3/3 제품 존재), **+자재 입고·투입**(LOT 역추적의 전제), **+불량유형 마스터**(검사기록에 불량실적 흡수).

1. **공정 마스터** `process_master` — 코드·공정명·유형(사내/외주)·검사 연계
2. **품목 마스터** `item_master` — 코드·품명·유형(원자재/반제품/완제품)·규격·고객품번(최대 3)·차종·주설비
   - **품목별 LOT 추적 플래그**(pop_item.TRACE_GBN): 전 품목 강제가 아니라 품목 단위 opt-in — 얇게 시작하는 장치
   - **업체LOT→내부LOT 승계 플래그**(INLOTUSE): 입고 시 밀시트/업체 로트를 그대로 내부 로트로 — 입고 파일럿의 핵심 단순화
   - 수입검사여부(INSP_SKIP)·출하검사여부(QC_GBN_O)·외주유무(OUT_YN)
3. **BOM** `bom_edge` — 상위·하위·소요량 (기존 0006 BOM과 정합화, 반제품 노드 포함 체인)
4. **라우팅** `routing_step` — 품목·순번·공정·외주여부 → 공정↔검사양식 연결의 척추
5. **거래처 마스터** `partner` — 고객/외주처/자재공급처 → 수입검사·성적서·출하 연결
6. **불량유형 마스터** `defect_type` — 공정별 불량 코드(2022 pop_code ROUTEBAD 계열과 호환)

**기록 테이블 5종** (2022 스키마 패턴 채택):

- **작업지시** `work_order` — 경량: 품목·수량·기간·라인(일괄 등록 지원 = VOC 헌법 §6-3). 실적의 앵커일 뿐 계획 최적화 ❌
- **자재 입고·투입** `mat_receipt` / `mat_issue` — 입고(업체LOT 승계=INLOTUSE)와 생산 LOT 투입 연결만. 창고·수불부 ❌

- **생산실적** `prod_record` — 일자+지시+순번 PK, 품번·LOT·작업장·설비·양품/불량수량·주야·시작/종료시각·작업자(세션 강제)
- **검사스펙** `insp_spec` — 품번×검사항목: 규격상한/하한(SU/SL)·관리상한/하한(MU/ML)·표준값(NOMINAL)·시료수 — MES 덤프 판독(SU/SL=NOM±공차)과 동일 구조라 TPC 연동 즉시 호환
- **검사기록** `insp_record` — 헤더(LOT·검사자·공정)+상세(시료별 측정값) — CP/CPK 자동 산출의 원천
- (후순위) 금형 타발카운트: 실적 연동 자동 증가 + A/B/C 등급별 한계 → 금형 PM 의무(#60·L1100-25)와 연결

## 5. LOT 흐름 — 사진 우선 설계 (사장님 안)

원칙: **현장 일을 더하지 않는다. 종이는 그대로, 증거만 디지털.**

1. LOT 자동 발번: `품번-YYMMDD-차수` — 사람은 번호를 치지 않는다 (작업지시/실적 등록 순간 시스템 발번, QR 라벨 출력)
2. 현장 기록 = 기존 종이 그대로 작성 → **사진 촬영 업로드** (PhotoField 웹 작동 기확인). 공정 마치기 전 올려도 LOT 체인은 유효
3. **공정 게이트**: 앞공정 사진 미업로드 → 뒷공정 등록 시 **알람(경고)**. 운영 안정 후 설정으로 **차단** 전환 가능
   - ★현장 정합성 실증: 2024 작업자 VOC 1번이 스스로 **"실적등록이 안 되면 종료 안 되게"**를 요구 — 게이트는 관리자 강요가 아니라 현장 요구였음
4. 입고는 **업체LOT 승계**(INLOTUSE 패턴)로 발번 없이 스캔/선택 1회
5. 후속 단계: AI 판독(OCR)으로 사진→구조화 데이터 추출 → Cpk 등 자동 산출로 승격
6. 조작차단 정합: 업로드 타임스탬프 + 세션 기록주체(W3 STAMP_FIELDS) 그대로 적용 — "언제·누가"는 위조 불가

## 6. 현장 VOC 교훈 (2022·2024 실측) — 설계 헌법

실제 TPC 현장이 MES에 던진 불만에서 추출한 규칙. 범용 제품이 같은 함정을 밟지 않게 하는 헌법.

1. **성능이 생사** — "박스당 실적 등록 로딩 5분" (작업자 VOC). 현장 화면은 1~2초 응답이 아니면 죽는다
2. **이어하기** — "작업장 이동 후 자주검사를 처음부터 다시" 금지. 중단·재개 가능해야 함
3. **일괄 등록** — "월초 한달치 수주/지시 일괄 등록" 요구. 지시가 없어 작업자가 실적을 못 넣는 병목 제거 (KPI 일괄입력 화면과 같은 철학)
4. **사람 경유 제거** — 불량 등록이 4명 경유(작업자→회수확인→실적등록→처리)라 오류. 발생 지점에서 1회 입력, 나머지는 시스템이 라우팅
5. **현장 화면 문법** — 큰 버튼·키패드·현재 생산품목만 표시·작업자 자동=검사자(2022 요구사항 그대로) — 우리 P5~P7 정답따라쓰기·작성자 auto와 동일 철학
6. **★기록처 없는 품질 프로세스** — 관리자 VOC 1번: "이상발생조치서, 어디다 기록해야 하나? MES?" — **MES는 품질 프로세스 문서의 집이 아니다.** 부적합·조치·8D·심사 증거는 우리 앱의 자리라는 현장 실증

## 7. 범위 경계 — SJIT/SWIT 표준 기능 리스트 기준

> **경계 원칙(코워크 결정 #3, 사장님 도장 대기): "돈·기계·재고는 안 만진다 — 물건의 품질과 사람의 할 일만 만진다."**

**한다 (반-MES 범위):**

- 기준정보(품목·거래처·BOM·라우팅·공정) / 작업지시(경량, 일괄등록 지원) / 생산실적·LOT 이력·투입LOT / QR 라벨
- 검사(수입·자주·패트롤·출하 — 사진 우선, 스펙=SU/SL/NOMINAL) / 불량 등록(1회 입력) / 4M·계측기(기존 기능 연결)
- 설비·금형 점검(기존 의무 #60·L1100-25 통합) / 경영정보 = 관제탑 확장(LOT 스토리·심사 대시보드)

**안 한다 (명시적 제외):**

- 단가/발주금액/매입/매출/거래명세서 · 재고 실사/로케이션 · 수주납품계획 · 근태·급여 일체 (ERP성)
- **생산계획/스케줄링(APS)** — 작업지시는 실적의 앵커로만. 수주·납기 최적화로 미끄러지는 순간 ERP 전쟁
- **설비 PLC 게더링·DAQ** (2024 고도화 영역 — 하드웨어 공사, 공급기업 몫) · SCM 외주 포털
